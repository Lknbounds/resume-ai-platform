# 步骤 05：简历与多版本管理（5 小时）

> **目标**：新建简历（自动生成 v1）、连续新增 v2/v3、查看版本列表和某个版本的全文；重复内容不会产生空版本；两个用户互相看不到对方的简历。
>
> 这是整个项目的**数据地基**：后面的分析、对比、社区发帖全部挂在"某个简历版本"上。

---

## 5.1 这一步做出什么

| 场景 | 行为 |
|---|---|
| 新建简历 | 填标题 + 粘贴正文（≥50 字）→ 自动生成 `v1`，返回 `currentVersionId` |
| 内容太短 | 400 + `code=40004` |
| 新增版本 | 提交新正文 → `version_no` 递增，`parent_version_id` 指向上一版 |
| 内容没变 | 400 + `code=10000`（"内容未变化"），**不产生空版本** |
| 版本列表 | 按 `version_no` 倒序，显示来源（粘贴/编辑/采纳评论）和字数 |
| 查看某版本 | 返回全文（用于编辑器回填） |
| 删除简历 | 级联删掉所有版本（后续的分析报告也会被级联删） |
| 越权 | A 访问 B 的简历 → 403 + `code=10002` |

---

## 5.2 为什么这样设计（面试可讲）

**① 为什么要"简历 + 版本"两张表，而不是一张表存全部内容？**
一份简历会被反复修改：一稿投大厂、二稿改量化、三稿采纳社区建议。如果一张表反复 UPDATE，历史就没了 —— 而**版本对比**和**"这次分析是针对哪一版"**都依赖历史。
所以拆成：
- `resume`：逻辑主体（标题、当前版本指针、版本数）；
- `resume_version`：**内容不可变**（每次修改插入新行，永不 UPDATE 正文）。

这样做的好处：任何一次分析报告都能精确指向"当时那一版"，三个月后回看仍是同一份内容。

**② 为什么 `resume_version.content` 要"不可变"？**
可变内容会让所有历史快照失效：报告说"你的项目描述缺少量化"，用户把正文改了，你再打开那份报告就找不到证据句子了。不可变 = 可复现，这是整个评估类产品的底线。

**③ 为什么 `resume.current_version_id` 不加外键？**
`resume` 和 `resume_version` 互相引用：插入顺序上"先有简历才能插版本"，而"版本要回填到简历的 current_version_id"。两边都建外键会形成循环依赖，删除/插入都可能报约束错误。
所以：`resume_version.resume_id` 建外键（真正的归属关系），`resume.current_version_id` 只建普通索引，由 Service 在**同一个事务**里保证一致。

**④ 版本号并发怎么办？**
两个人同时对同一份简历点"保存新版本"，如果都读到 `max=2` 然后都插 `3`，`uk_version_no(resume_id, version_no)` 唯一键会让其中一个失败 —— 不会脏数据，但用户会看到莫名其妙的报错。
处理：在事务里用 `SELECT ... FOR UPDATE` 锁住 `resume` 那一行，串行化"算版本号 + 插入"。锁的粒度只有一行，成本很低。

**⑤ 为什么要存 `content_hash`？**
- **防空版本**：用户点保存但没改内容 → hash 相同 → 直接拒绝，不浪费存储和版本号；
- **给缓存做 key**：同一个版本内容的解析结果可以缓存 30 天（步骤 8 用）；
- 内容不可变，所以 hash 天然稳定。

**⑥ 为什么实体之间不用 `@ManyToOne` 关联，只存 id？**
JPA 的 `@ManyToOne(fetch = LAZY)` 在 `open-in-view: false`（本项目配置）下，**出了事务再访问就会抛 `LazyInitializationException`**。要避免就得写 `JOIN FETCH` 或 `@EntityGraph`，代码复杂度陡增。
而本项目的关联几乎都是"一对多 + 只需要 id"，直接存 `Long resumeId` 后：
- 不会有意外的懒加载；
- DTO 组装时显式决定要不要多查一次（而不是隐式 N+1）；
- 实体之间零耦合，改一个模块不影响另一个。

代价是"要自己保证外键一致性"，而这一点由**数据库外键**兜底（我们建了 `fk_version_resume`）。这是很典型的"用 DB 约束换 ORM 简洁"的取舍。

**⑦ 内容为什么要归一化？**
用户从 Word 复制过来的文本可能带 `\r\n`、BOM、制表符、连续空格。不归一化会有两个问题：同样的内容算出不同 hash（缓存失效）、diff 时每行都"变了"（步骤 6 的问题）。
统一规则：`\r\n → \n`、去 BOM、行尾空白去掉、连续 3 个以上空行压成 2 个。

```java
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "user_id", nullable = false)
    private Long userId;

    @Column(nullable = false, length = 64)
    private String title;

    @Column(name = "current_version_id")
    private Long currentVersionId;

    @Column(name = "version_count", nullable = false)
    private Integer versionCount;

    @Column(name = "created_at", nullable = false, updatable = false)
    private LocalDateTime createdAt;

    @Column(name = "updated_at", nullable = false)
    private LocalDateTime updatedAt;

    @PrePersist
    void onCreate() {
        LocalDateTime now = LocalDateTime.now(ZoneOffset.UTC);
        if (createdAt == null) createdAt = now;
        updatedAt = now;
        if (versionCount == null) versionCount = 0;
    }

    @PreUpdate
    void onUpdate() { updatedAt = LocalDateTime.now(ZoneOffset.UTC); }
}
```

### 5.4.5 文本归一化 + hash

```java
package com.jianli.resume.service;

import org.springframework.stereotype.Component;

import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.security.NoSuchAlgorithmException;
import java.util.HexFormat;

@Component
public class ResumeTextNormalizer {

    /** 统一换行、去 BOM、去行尾空白、压缩空行 */
    public String normalize(String raw) {
        if (raw == null) return "";
        String t = raw.replace("﻿", "")          // BOM
                      .replace("\r\n", "\n")
                      .replace('\r', '\n');

        String[] lines = t.split("\n", -1);
        StringBuilder sb = new StringBuilder(t.length());
        int blankRun = 0;
        for (String line : lines) {
            String trimmed = line.replaceAll("[ \t　]+$", "");
            if (trimmed.isBlank()) {
                blankRun++;
                if (blankRun > 2) continue;            // 最多保留 2 个连续空行
                sb.append('\n');
            } else {
                blankRun = 0;
                sb.append(trimmed).append('\n');
            }
        }
        return sb.toString().strip();
    }

    public int charCount(String normalized) {
        return normalized.replaceAll("\\s", "").length();
    }

    public String sha256(String text) {
        try {
            MessageDigest md = MessageDigest.getInstance("SHA-256");
            return HexFormat.of().formatHex(md.digest(text.getBytes(StandardCharsets.UTF_8)));
        } catch (NoSuchAlgorithmException e) {
            throw new IllegalStateException("SHA-256 不可用", e);
        }
    }
}
```

> `charCount` 去掉了所有空白字符再计数 —— 因为"至少 50 字"的用户预期是"50 个实际字"，不是"50 个字符（含大量空格）"。

### 5.4.7 Service

```java
package com.jianli.resume.service;

import com.jianli.common.*;
import com.jianli.resume.dto.*;
import com.jianli.resume.entity.Resume;
import com.jianli.resume.entity.ResumeVersion;
import com.jianli.resume.enums.VersionSource;
import com.jianli.resume.repository.ResumeRepository;
import com.jianli.resume.repository.ResumeVersionRepository;
import lombok.RequiredArgsConstructor;
import org.springframework.data.domain.Page;
import org.springframework.data.domain.PageRequest;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.List;

@Service
@RequiredArgsConstructor
public class ResumeService {

    private static final int MIN_CHARS = 50;

    private final ResumeRepository resumeRepository;
    private final ResumeVersionRepository versionRepository;
    private final ResumeTextNormalizer normalizer;

    // ---------- 新建 ----------
    @Transactional
    public ResumeDetailVO create(Long userId, CreateResumeRequest req) {
        String content = normalizeChecked(req.content());

        Resume resume = new Resume();
        resume.setUserId(userId);
        resume.setTitle(req.title());
        resume.setVersionCount(0);
        resume = resumeRepository.save(resume);

        ResumeVersion v1 = buildVersion(resume.getId(), 1, content,
                VersionSource.PASTE, null, "初始版本");
        v1 = versionRepository.save(v1);

        resume.setCurrentVersionId(v1.getId());
        resume.setVersionCount(1);

        return detailOf(resume);
    }

    // ---------- 新增版本 ----------
    @Transactional
    public VersionDetailVO addVersion(Long userId, Long resumeId, AddVersionRequest req) {
        // FOR UPDATE：并发时版本号不会撞车
        Resume resume = resumeRepository.findByIdForUpdate(resumeId)
                .filter(r -> r.getUserId().equals(userId))
                .orElseThrow(() -> new BizException(ErrorCode.RESUME_NOT_FOUND));

        String content = normalizeChecked(req.content());
        String hash = normalizer.sha256(content);

        if (versionRepository.findFirstByResumeIdAndContentHash(resumeId, hash).isPresent()) {
            throw new BizException(ErrorCode.PARAM_INVALID, "内容与已有版本相同，未创建新版本");
        }

        int nextNo = versionRepository.findMaxVersionNo(resumeId) + 1;
        ResumeVersion v = buildVersion(resumeId, nextNo, content,
                req.source() == null ? VersionSource.EDIT : req.source(),
                resume.getCurrentVersionId(), req.changeNote());
        v = versionRepository.save(v);

        resume.setCurrentVersionId(v.getId());
        resume.setVersionCount(resume.getVersionCount() + 1);

        return toDetail(v);
    }

    // ---------- 查询 ----------
    @Transactional(readOnly = true)
    public PageResult<ResumeSummaryVO> list(Long userId, int page, int size) {
        Page<Resume> p = resumeRepository.findByUserIdOrderByUpdatedAtDesc(
                userId, PageRequest.of(Math.max(page - 1, 0), Math.min(size, 50)));
        List<ResumeSummaryVO> vos = p.getContent().stream().map(r -> new ResumeSummaryVO(
                r.getId(), r.getTitle(), r.getCurrentVersionId(), r.getVersionCount(),
                null, r.getUpdatedAt())).toList();
        return new PageResult<>(vos, p.getTotalElements(), page, p.getSize(), p.getTotalPages());
    }

    @Transactional(readOnly = true)
    public ResumeDetailVO detail(Long userId, Long resumeId) {
        Resume resume = resumeRepository.findByIdAndUserId(resumeId, userId)
                .orElseThrow(() -> new BizException(ErrorCode.RESUME_NOT_FOUND));
        return detailOf(resume);
    }

    @Transactional(readOnly = true)
    public VersionDetailVO getVersion(Long userId, Long versionId) {
        ResumeVersion v = versionRepository.findById(versionId)
                .orElseThrow(() -> new BizException(ErrorCode.VERSION_NOT_FOUND));
        // 越权校验：版本必须属于"我的某份简历"
        resumeRepository.findByIdAndUserId(v.getResumeId(), userId)
                .orElseThrow(() -> new BizException(ErrorCode.FORBIDDEN));
        return toDetail(v);
    }

    @Transactional
    public void delete(Long userId, Long resumeId) {
        Resume resume = resumeRepository.findByIdAndUserId(resumeId, userId)
                .orElseThrow(() -> new BizException(ErrorCode.RESUME_NOT_FOUND));
        resumeRepository.delete(resume);   // 数据库外键 ON DELETE CASCADE 级联删版本
    }

    @Transactional
    public ResumeDetailVO rename(Long userId, Long resumeId, String title) {
        Resume resume = resumeRepository.findByIdAndUserId(resumeId, userId)
                .orElseThrow(() -> new BizException(ErrorCode.RESUME_NOT_FOUND));
        resume.setTitle(title);
        return detailOf(resume);
    }

    // ---------- 内部 ----------
    /** 供其他模块复用：拿到版本并校验归属 */
    @Transactional(readOnly = true)
    public ResumeVersion requireOwnedVersion(Long userId, Long versionId) {
        ResumeVersion v = versionRepository.findById(versionId)
                .orElseThrow(() -> new BizException(ErrorCode.VERSION_NOT_FOUND));
        resumeRepository.findByIdAndUserId(v.getResumeId(), userId)
                .orElseThrow(() -> new BizException(ErrorCode.FORBIDDEN));
        return v;
    }

    private String normalizeChecked(String raw) {
        String content = normalizer.normalize(raw);
        if (normalizer.charCount(content) < MIN_CHARS) {
            throw new BizException(ErrorCode.RESUME_CONTENT_INVALID);
        }
        return content;
    }

    private ResumeVersion buildVersion(Long resumeId, int no, String content,
                                       VersionSource source, Long parentId, String note) {
        ResumeVersion v = new ResumeVersion();
        v.setResumeId(resumeId);
        v.setVersionNo(no);
        v.setContent(content);
        v.setContentHash(normalizer.sha256(content));
        v.setSource(source);
        v.setParentVersionId(parentId);
        v.setChangeNote(note);
        v.setCharCount(normalizer.charCount(content));
        return v;
    }

    private ResumeDetailVO detailOf(Resume r) {
        List<VersionSummaryVO> versions = versionRepository
                .findByResumeIdOrderByVersionNoDesc(r.getId())
                .stream().map(VersionSummaryVO::of).toList();
        return new ResumeDetailVO(r.getId(), r.getTitle(), r.getCurrentVersionId(),
                r.getVersionCount(), versions, r.getCreatedAt(), r.getUpdatedAt());
    }

    private VersionDetailVO toDetail(ResumeVersion v) {
        return new VersionDetailVO(v.getId(), v.getResumeId(), v.getVersionNo(), v.getContent(),
                v.getCharCount(), v.getContentHash(), v.getSource(),
                v.getParentVersionId(), v.getChangeNote(), v.getCreatedAt());
    }
}
```

> `requireOwnedVersion` 是**故意暴露的复用点**：步骤 8 的分析、步骤 15 的面试题都要"拿到一个属于当前用户的版本"，复用它可以避免每个模块重复写越权校验（也避免漏写）。

```java
package com.jianli.resume.controller;

import com.jianli.common.ApiResponse;
import com.jianli.common.CurrentUserId;
import com.jianli.common.PageResult;
import com.jianli.resume.dto.*;
import com.jianli.resume.service.ResumeService;
import io.swagger.v3.oas.annotations.tags.Tag;
import jakarta.validation.Valid;
import lombok.RequiredArgsConstructor;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/resumes")
@Tag(name = "简历")
@RequiredArgsConstructor
public class ResumeController {

    private final ResumeService resumeService;

    @PostMapping
    public ResponseEntity<ApiResponse<ResumeDetailVO>> create(
            @CurrentUserId Long userId, @RequestBody @Valid CreateResumeRequest req) {
        return ResponseEntity.status(HttpStatus.CREATED)
                .body(ApiResponse.ok(resumeService.create(userId, req)));
    }

    @GetMapping
    public ApiResponse<PageResult<ResumeSummaryVO>> list(
            @CurrentUserId Long userId,
            @RequestParam(defaultValue = "1") int page,
            @RequestParam(defaultValue = "10") int size) {
        return ApiResponse.ok(resumeService.list(userId, page, size));
    }

    @GetMapping("/{id}")
    public ApiResponse<ResumeDetailVO> detail(@CurrentUserId Long userId, @PathVariable Long id) {
        return ApiResponse.ok(resumeService.detail(userId, id));
    }

    @PutMapping("/{id}")
    public ApiResponse<ResumeDetailVO> rename(@CurrentUserId Long userId, @PathVariable Long id,
                                              @RequestBody @Valid RenameRequest req) {
        return ApiResponse.ok(resumeService.rename(userId, id, req.title()));
    }

    @DeleteMapping("/{id}")
    public ApiResponse<Void> delete(@CurrentUserId Long userId, @PathVariable Long id) {
        resumeService.delete(userId, id);
        return ApiResponse.ok();
    }

    @PostMapping("/{id}/versions")
    public ResponseEntity<ApiResponse<VersionDetailVO>> addVersion(
            @CurrentUserId Long userId, @PathVariable Long id,
            @RequestBody @Valid AddVersionRequest req) {
        return ResponseEntity.status(HttpStatus.CREATED)
                .body(ApiResponse.ok(resumeService.addVersion(userId, id, req)));
    }

    @GetMapping("/versions/{versionId}")
    public ApiResponse<VersionDetailVO> version(@CurrentUserId Long userId,
                                                @PathVariable Long versionId) {
        return ApiResponse.ok(resumeService.getVersion(userId, versionId));
    }

    public record RenameRequest(@jakarta.validation.constraints.NotBlank
                                @jakarta.validation.constraints.Size(max = 64) String title) {}
}
```

> **路径冲突提醒**：`GET /api/resumes/{id}` 和 `GET /api/resumes/versions/{versionId}` 同时存在时，Spring 能正确区分（`versions` 是字面量片段，优先级高于变量）。但为避免歧义，`versions` 路由必须写在 `{id}` **后面**也更稳妥（本项目实际上不冲突，因为 `/versions/{versionId}` 有两段）。

```js
import http from './http'

export const resumeApi = {
  list: (params) => http.get('/resumes', { params }),
  detail: (id) => http.get(`/resumes/${id}`),
  create: (data) => http.post('/resumes', data),
```

### 5.5.2 `src/stores/resume.js`

```js
import { defineStore } from 'pinia'
import { resumeApi } from '@/api/resume'

export const useResumeStore = defineStore('resume', {
  state: () => ({
    list: [],
    total: 0,
    current: null,        // 简历详情（含版本列表）
    currentVersion: null, // 某个版本的全文
    loading: false
  }),

  actions: {
    async fetchList(page = 1, size = 10) {
      this.loading = true
      try {
        const data = await resumeApi.list({ page, size })
        this.list = data.records
        this.total = data.total
      } finally {
        this.loading = false
      }
    },

    async fetchDetail(id) {
      this.current = await resumeApi.detail(id)
      return this.current
    },

    async create(payload) {
      const data = await resumeApi.create(payload)
      this.current = data
      return data
    },

    async addVersion(id, payload) {
      const v = await resumeApi.addVersion(id, payload)
      await this.fetchDetail(id)
      return v
    },

    async fetchVersion(versionId) {
      this.currentVersion = await resumeApi.version(versionId)
      return this.currentVersion
    }
  }
})
```

```vue
<script setup>
import { reactive, ref, onMounted } from 'vue'
import { useRouter } from 'vue-router'
import { ElMessage, ElMessageBox } from 'element-plus'
import DefaultLayout from '@/layouts/DefaultLayout.vue'
import { useResumeStore } from '@/stores/resume'
import { resumeApi } from '@/api/resume'

const router = useRouter()
const store = useResumeStore()

const dialogVisible = ref(false)
const submitting = ref(false)

  form.title = ''
  form.content = ''
  dialogVisible.value = true

async function submit() {

  store.fetchList(page.value, size.value)
}
```

### 5.5.4 简历详情页 `src/views/resume/ResumeDetailView.vue`

左侧版本时间线，右侧全文；"另存为新版本"按钮（内容未改动时禁用）。

```vue
<script setup>
import { ref, computed, onMounted, watch } from 'vue'
import { useRoute } from 'vue-router'
import { ElMessage } from 'element-plus'
import DefaultLayout from '@/layouts/DefaultLayout.vue'
import { useResumeStore } from '@/stores/resume'

const route = useRoute()
const store = useResumeStore()
const activeVersionId = ref(null)
const editing = ref(false)
const draft = ref('')
const saving = ref(false)
const changeNote = ref('')

const version = computed(() => store.currentVersion)

onMounted(async () => {
  const detail = await store.fetchDetail(route.params.id)
  activeVersionId.value = detail.currentVersionId
  await loadVersion(activeVersionId.value)
})

watch(activeVersionId, (id) => { if (id) loadVersion(id) })

async function loadVersion(id) {
  const v = await store.fetchVersion(id)
  draft.value = v.content
  editing.value = false
}

function startEdit() {
  editing.value = true
}

async function saveNewVersion() {
  if (draft.value.replace(/\s/g, '').length < 50) return ElMessage.warning('至少 50 字')
  saving.value = true
  try {
    await store.addVersion(store.current.id, {
      content: draft.value,
      changeNote: changeNote.value || null,
      source: 'EDIT'
    })
    ElMessage.success('已保存为新版本')
    const detail = store.current
    activeVersionId.value = detail.currentVersionId
    changeNote.value = ''
  } finally {
    saving.value = false
  }
}
</script>

<template>
  <DefaultLayout>
    <el-row :gutter="16" v-if="store.current">
      <el-col :span="6">
        <el-card shadow="never">
          <template #header>版本记录（{{ store.current.versionCount }}）</template>
          <el-timeline>
            <el-timeline-item
              v-for="v in store.current.versions" :key="v.id"
              :timestamp="v.createdAt" placement="top"
              :type="v.id === store.current.currentVersionId ? 'primary' : ''">
              <div class="ver" :class="{ active: v.id === activeVersionId }" @click="activeVersionId = v.id">
                <div class="ver-title">v{{ v.versionNo }} · {{ v.charCount }} 字</div>
                <div class="ver-note">{{ v.changeNote || v.source }}</div>
              </div>
            </el-timeline-item>
          </el-timeline>
        </el-card>
      </el-col>

      <el-col :span="18">
        <el-card shadow="never">
          <template #header>
            <div class="head">
              <span>{{ store.current.title }} · v{{ version?.versionNo }}</span>
              <div>
                <el-button v-if="!editing" @click="startEdit">编辑内容</el-button>
                <template v-else>
                  <el-input v-model="changeNote" placeholder="变更说明（可选）" style="width: 200px; margin-right: 8px" />
                  <el-button @click="loadVersion(activeVersionId)">取消</el-button>
                  <el-button type="primary" :loading="saving" @click="saveNewVersion">保存为新版本</el-button>
                </template>
              </div>
            </div>
          </template>

          <el-input v-if="editing" v-model="draft" type="textarea" :rows="28" />
          <div v-else class="pre-wrap">{{ version?.content }}</div>
        </el-card>
      </el-col>
    </el-row>
  </DefaultLayout>
</template>

<style scoped>
.head { display: flex; justify-content: space-between; align-items: center; }
.ver { cursor: pointer; padding: 6px 8px; border-radius: 6px; }
.ver:hover { background: #f5f7fa; }
.ver.active { background: #ecf5ff; }
```

## 5.6 验证

### 后端（curl）

```bash
TOKEN=<登录拿到的 accessToken>
H="-H Authorization:Bearer\ $TOKEN -H Content-Type:application/json"

# ① 新建（正文自己粘一段 >50 字）
curl -s -X POST http://localhost:8080/api/resumes \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"title":"Java 后端简历","content":"张三 后端开发工程师\n教育背景：某大学 计算机科学与技术 本科 2018-2022\n工作经历：某公司 Java 开发 2022.07-2024.06 负责订单系统开发与维护\n专业技能：Java Spring Boot MySQL Redis"}'
# 期望：code=0，versions 里有 1 条 v1，currentVersionId 有值

# ② 记下简历 id 和 v1 内容，新增 v2（改几个字）
curl -s -X POST http://localhost:8080/api/resumes/1/versions \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"content":"（把上面的内容改一处）...","changeNote":"补充量化数据","source":"EDIT"}'
# 期望：versionNo=2，parentVersionId=v1 的 id

# ③ 用完全相同的内容再提交一次
# 期望：code=10000，message 含"内容与已有版本相同"

# ④ 内容太短
curl -s -X POST http://localhost:8080/api/resumes -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -d '{"title":"x","content":"太短"}'
# 期望：code=40004

# ⑤ 越权：用 bob 登录拿 bobToken，访问 alice 的简历
# 期望：code=40001（"简历不存在"，因为查询带了 user_id 条件）
```

> **为什么越权返回"不存在"而不是"无权限"**：`findByIdAndUserId` 查不到就直接当不存在。这比"先查再判断"更安全（不泄露"这个 id 存在"的信息），也少一次判断。

### 数据核对

```bash
"$M" -uroot -p123456 --default-character-set=utf8mb4 resume_ai -e "
SELECT r.id, r.title, r.version_count, r.current_version_id,
       v.version_no, v.char_count, LEFT(v.content_hash,8) AS hash8, v.source
FROM resume r JOIN resume_version v ON v.resume_id = r.id ORDER BY r.id, v.version_no;"
# 期望：version_count 与版本行数一致；current_version_id = 最大 version_no 的 id
```

### 前端

| 操作 | 期望 |
|---|---|
| 我的简历 → 粘贴新简历 | 创建后跳到详情页，左侧时间线有 v1 |
| 点"编辑内容"改几个字 → 保存为新版本 | 时间线多出 v2，并自动选中 |
| 原样不改再保存 | 提示"内容与已有版本相同" |

| 删除简历 | 列表里消失；库里 `resume_version` 也没了（级联） |

## 5.7 报错怎么办

| 现象 | 原因 | 解决 |
|---|---|---|
| `Duplicate entry ... uk_version_no` | 并发时锁没生效 | 确认 `addVersion` 用的是 `findByIdForUpdate` |
| 版本号从 0 或重复 | `findMaxVersionNo` 的 `coalesce` 没写 | 无版本时应返回 0 |
| 相同内容也能建版本 | 只在 resume 内比较 hash 还不够时（不同简历） | 本项目只要求同简历内判重，符合预期 |
| 详情页右侧空白 | `activeVersionId` 没赋值 | `onMounted` 里先 `fetchDetail` 再 `loadVersion` |
| 中文乱码存进库 | 连接串缺 `characterEncoding=utf8` | 检查 `application.yml` 的 JDBC URL |
| 删除简历报外键错误 | 报告表还引用着版本 | 数据库已配 `ON DELETE CASCADE`，确认 DDL 没被改 |
| 保存新版本后时间线没刷新 | 只改了本地状态 | `addVersion` 后调 `fetchDetail` 重新拉 |

## 5.8 自测题

1. **为什么版本内容要不可变？** → 所有历史报告/快照都指向它，改了历史就失真了。
2. **`current_version_id` 为什么不建外键？** → 与 `resume_version.resume_id` 形成循环依赖，插入/删除顺序无解。
3. **版本号并发怎么保证唯一？** → `SELECT ... FOR UPDATE` 锁住简历行串行化 + `uk_version_no` 唯一键兜底。
4. **为什么存 content_hash？** → 防空版本 + 作为解析缓存 key（内容不可变故 hash 稳定）。
5. **为什么不写 `@ManyToOne`？** → 避免 `open-in-view=false` 下的懒加载异常与隐式 N+1，用数据库外键保证一致性。
6. **越权为什么返回"不存在"？** → 不泄露资源是否存在，且少一次判断。
