# 步骤 11：SSE 进度推送（5 小时）

> **目标**：发起分析后，前端进度条按阶段推进（解析 JD → 解析简历 → 语义匹配 → 计算分数 → 生成建议），中途刷新页面能恢复，AI 降级时弹黄条提示。
>
> 在此之前，用户只能干等着看"分析中"。这一步做完，"等 8 秒"的体验才不算糟。

---

## 11.1 这一步做出什么

```
POST /api/analyses                → 202 {reportId, status:"PENDING"}
GET  /api/analyses/{id}/stream    → text/event-stream
  event: stage   {"stage":"JD_PARSE","progress":10,"message":"正在解析岗位要求"}
  event: stage   {"stage":"RESUME_PARSE","progress":30,"message":"正在解析简历"}
  event: warning {"code":30003,"message":"AI 语义匹配超时，已降级为词典匹配"}
  event: stage   {"stage":"SCORING","progress":80,"message":"正在计算匹配分"}
  event: stage   {"stage":"SUGGESTION","progress":92,"message":"正在生成改进建议"}
  event: done    {"reportId":77,"status":"PARTIAL","overallScore":70.8}
```

| 场景 | 行为 |
|---|---|
| 正常 | 5 个 stage → done |
| AI 降级 | 多一个 `warning` 事件，`done.status=PARTIAL` |
| 失败 | `event: error {"code":42003}` |
| 刷新页面 | 重新订阅，若已完成则**立刻补发 done** |
| 客户端断开 | 服务端自动清理，不泄漏 |
| 代理超时 | 每 15s 一个 `: ping` 心跳保活 |
| SSE 不可用 | 前端重试 3 次后退化为轮询 |

---

## 11.2 为什么这样设计（面试可讲）

**① 为什么用 SSE 而不是 WebSocket？**
需求是**单向推送**（服务端 → 浏览器）。SSE 就是普通 HTTP 长连接（`text/event-stream`），Nginx 只需 `proxy_buffering off`，鉴权、日志、部署方式都和普通接口一致。
WebSocket 要处理握手升级、心跳、重连、代理配置，收益为零。**只有需要"客户端频繁主动推送"时才值得上 WS。**

**② 为什么不用原生 `EventSource`？**
`EventSource` 不能设置请求头，只能把 token 拼在 URL 上（`?token=xxx`）。这会导致 token 进入 Nginx access log、浏览器历史、Referer。
所以前端用 **`fetch` + `ReadableStream` 手动解析 SSE**（约 40 行），继续用 `Authorization` 头，还能用 `AbortController` 优雅取消。

**③ 为什么进度是"服务器推"而不是"前端定时轮询"？**
轮询在 8 秒内要发 16 次请求（每 500ms），其中 15 次是"没变化"。SSE 只在变化时推一次，且首字节延迟低。
但**轮询要做成降级方案**：老代理、企业网络可能掐掉长连接，此时轮询至少能保证结果最终出现。

**④ 为什么必须有心跳？**
Nginx `proxy_read_timeout` 默认 60s，中间代理、公司防火墙常在空闲 30-60s 时断连。SSE 规范里 `:` 开头的行是注释，不发事件但能重置超时计时器。所以每 15s 发一个 `: ping`。

**⑤ 为什么"刷新页面后要补发 done"？**
用户刷新时连接断了，服务端没人在听。重连时如果报告已经完成，必须立刻补一个 `done`，否则前端会一直等（进度条卡在 30%）。
实现：Controller 里判断报告状态，若已完成 → 发送 done → 稍延迟后 `emitter.complete()`。

**⑥ 为什么"稍延迟"关闭？**
如果 `send` 之后立刻 `complete()`，响应头和事件可能还没真正 flush，前端拿到的是空响应。延迟 100-200ms 或放到 `CompletableFuture.runAsync` 里执行都行。这是 SSE 一个很隐蔽的坑。

**⑦ 为什么任务在独立线程池，而 SSE 只负责转发？**
SSE 连接会占用一个 Tomcat 线程直到关闭。如果让"分析逻辑"也在这个线程里跑，一个用户就会占 2 个线程（一个算、一个推）。所以：分析在 `analysisExecutor`，SSE 线程只挂在那里等事件（异步 Servlet，Tomcat 线程实际会被释放，但连接占用不变）。

**⑧ 为什么事件里要有 `progress` 和 `message` 两个字段？**
`progress` 给进度条，`message` 给"正在干什么"的文案。只有百分比的话，用户看着 60% 停 3 秒会以为卡死；有文案（"正在做语义匹配"）就能理解。

**⑨ 为什么用超时、而不是无限等待？**
`SseEmitter(180_000L)` 设 3 分钟上限。超过就关闭，前端会退化为轮询查结果。**任何长连接都必须有上限**，否则服务端会积累永远不会关闭的连接。

### 11.4.2 SseHub（注册表 + 心跳）

```java
package com.jianli.analysis.sse;

import lombok.extern.slf4j.Slf4j;
import org.springframework.http.MediaType;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;
import org.springframework.web.servlet.mvc.method.annotation.SseEmitter;

import java.io.IOException;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

@Slf4j
@Component
public class SseHub {

    private static final long TIMEOUT_MS = 180_000L;

    private final Map<Long, SseEmitter> emitters = new ConcurrentHashMap<>();

    public SseEmitter register(Long reportId) {
        SseEmitter old = emitters.remove(reportId);
        if (old != null) {
            try { old.complete(); } catch (Exception ignored) {}
        }

        SseEmitter emitter = new SseEmitter(TIMEOUT_MS);
        emitter.onCompletion(() -> emitters.remove(reportId));
        emitter.onTimeout(() -> {
            log.debug("sse timeout, reportId={}", reportId);
            emitters.remove(reportId);
            emitter.complete();
        });
        emitter.onError(e -> emitters.remove(reportId));
        emitters.put(reportId, emitter);

        log.debug("sse registered, reportId={}, total={}", reportId, emitters.size());
        return emitter;
    }

    public void send(Long reportId, String event, Object payload) {
        SseEmitter emitter = emitters.get(reportId);
        if (emitter == null) return;                // 没人在听，直接丢弃
        try {
            emitter.send(SseEmitter.event()
                    .name(event)
                    .data(payload, MediaType.APPLICATION_JSON));
        } catch (IOException | IllegalStateException e) {
            emitters.remove(reportId);              // 客户端已断开
        }
    }

    public void sendStage(Long reportId, AnalysisStage stage) {
        send(reportId, "stage", Map.of(
                "stage", stage.name(),
                "progress", stage.progress(),
                "message", stage.message()));
    }

    /** 心跳：防中间代理掐断空闲连接（SSE 规范中 ':' 开头为注释，前端会忽略） */
    @Scheduled(fixedDelay = 15_000)
    public void heartbeat() {
        emitters.forEach((id, emitter) -> {
            try {
                emitter.send(SseEmitter.event().comment("ping"));
            } catch (Exception e) {
                emitters.remove(id);
            }
        });
    }

    public boolean hasSubscriber(Long reportId) {
        return emitters.containsKey(reportId);
    }
}
```

> `@Scheduled` 需要启动类上的 `@EnableScheduling`（步骤 1 已加）。

### 11.4.4 Controller

```java
@GetMapping(value = "/{id}/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public SseEmitter stream(@CurrentUserId Long userId, @PathVariable Long id) {
    AnalysisReport report = analysisService.getOwned(userId, id);
    SseEmitter emitter = sseHub.register(id);

    // 已完成的任务：补发结果，否则前端会一直等
    boolean finished = List.of("SUCCESS", "PARTIAL", "FAILED").contains(report.getStatus());
    if (finished) {
        if ("FAILED".equals(report.getStatus())) {
            sseHub.send(id, "error", Map.of("code", 42003,
                    "message", report.getErrorMessage() == null ? "分析失败" : report.getErrorMessage()));
        } else {
            sseHub.send(id, "done", Map.of(
                    "reportId", id,
                    "status", report.getStatus(),
                    "overallScore", report.getOverallScore() == null
                            ? 0 : report.getOverallScore().doubleValue()));
        }
        // 延迟关闭：send 之后立刻 complete 可能导致前端拿到空响应
        CompletableFuture.runAsync(() -> {
            try { Thread.sleep(200); } catch (InterruptedException ignored) {}
            emitter.complete();
        });
    }
    return emitter;
}
```

**几个必须知道的细节：**

1. `produces = TEXT_EVENT_STREAM_VALUE` 不能少，否则 Spring 按 JSON 序列化。
2. **不能用 `@Transactional`**：事务提交会阻塞到方法返回，而 SseEmitter 是异步返回的，会导致响应迟迟不 flush。
3. 需要 `spring.mvc.async.request-timeout`（`application.yml` 已设 300s）不小于 `SseEmitter` 的 180s。
4. 安全：路径 `/api/analyses/**` 需要登录（`SecurityConfig` 已配），并且 `getOwned` 做归属校验 —— **不能让别人订阅你的分析进度**。

### 11.5.1 `src/utils/sse.js`

```js
/**
 * 基于 fetch 的 SSE 客户端：支持 Authorization 头、取消、自动抓取事件块。
 * @param {string} url
 * @param {{onEvent?: Function, onError?: Function, onClose?: Function, signal?: AbortSignal}} opts
 * @returns {{close: () => void}}
 */
export function createSseStream(url, { onEvent, onError, onClose, signal } = {}) {
  const controller = new AbortController()
  const mergedSignal = signal || controller.signal
  let closed = false

  const parseBlock = (raw) => {
    let name = 'message'
    const dataLines = []
    for (const line of raw.split(/\r?\n/)) {
      if (!line || line.startsWith(':')) continue
      if (line.startsWith('event:')) name = line.slice(6).trim()
      else if (line.startsWith('data:')) dataLines.push(line.slice(5).trim())
    }
    if (!dataLines.length) return null
    const text = dataLines.join('\n')
    let data
    try { data = JSON.parse(text) } catch { data = text }
    return { event: name, data }
  }

  const run = async () => {
    try {
      const res = await fetch(url, {
        headers: {
          Authorization: `Bearer ${localStorage.getItem('accessToken') || ''}`,
          Accept: 'text/event-stream'
        },
        signal: mergedSignal
      })
      if (!res.ok || !res.body) throw new Error(`SSE 连接失败: ${res.status}`)

      const reader = res.body.getReader()
      const decoder = new TextDecoder('utf-8')
      let buffer = ''

      while (!closed) {
        const { done, value } = await reader.read()
        if (done) break
        buffer += decoder.decode(value, { stream: true })

        let idx
        while ((idx = buffer.indexOf('\n\n')) >= 0) {
          const raw = buffer.slice(0, idx)
          buffer = buffer.slice(idx + 2)
          const evt = parseBlock(raw)
          if (evt) onEvent?.(evt)
        }
      }
      onClose?.()
    } catch (e) {
      if (e.name !== 'AbortError') onError?.(e)
    }
  }

  run()
  return { close: () => { closed = true; controller.abort() } }
}
```

### 11.5.2 `src/stores/analysis.js`

```js
import { defineStore } from 'pinia'
import http from '@/api/http'
import { createSseStream } from '@/utils/sse'

export const useAnalysisStore = defineStore('analysis', {
  state: () => ({
    report: null,
    progress: 0,
    stage: '',
    message: '',
    warnings: [],
    stream: null,
    pollingTimer: null
  }),

  actions: {
    async create(payload) {
      return http.post('/analyses', payload)
    },

    async fetch(id) {
      this.report = await http.get(`/analyses/${id}`)
      return this.report
    },

    connect(id, { onDone, onError } = {}) {
      this.closeStream()
      this.progress = 0
      this.warnings = []
      let retries = 0

      const open = () => {
        this.stream = createSseStream(`/api/analyses/${id}/stream`, {
          onEvent: ({ event, data }) => {
            if (event === 'stage') {
              this.stage = data.stage
              this.progress = data.progress
              this.message = data.message
            } else if (event === 'warning') {
              this.warnings.push(data.message)
            } else if (event === 'done') {
              this.progress = 100
              this.message = '完成'
              this.closeStream()
              onDone?.(data)
            } else if (event === 'error') {
              this.closeStream()
              onError?.(data)
            }
          },
          onError: () => {
            if (retries++ < 3) {
              setTimeout(open, 1000 * retries)     // 1s / 2s / 3s
            } else {
              this.startPolling(id, { onDone, onError })
            }
          },
          onClose: () => {
            if (this.progress < 100) this.startPolling(id, { onDone, onError })
          }
        })
      }

      open()
    },

    /** SSE 不可用时的兜底：每 2s 查一次，最多 60 次 */
    startPolling(id, { onDone, onError } = {}) {
      if (this.pollingTimer) return
      let n = 0
      this.pollingTimer = setInterval(async () => {
        n++
        try {
          const r = await this.fetch(id)
          if (r.status === 'SUCCESS' || r.status === 'PARTIAL') {
            this.stopPolling()
            this.progress = 100
            onDone?.(r)
          } else if (r.status === 'FAILED') {
            this.stopPolling()
            onError?.(r)
          } else if (n >= 60) {
            this.stopPolling()
            onError?.({ message: '分析超时，请稍后到报告列表查看' })
          } else {
            this.progress = 40
            this.message = '正在分析（轮询模式）'
          }
        } catch {
          this.stopPolling()
        }
      }, 2000)
    },

    stopPolling() {
      if (this.pollingTimer) { clearInterval(this.pollingTimer); this.pollingTimer = null }
    },

    closeStream() {
      this.stream?.close?.()
      this.stream = null
      this.stopPolling()
    }
  }
})
```

## 11.7 报错怎么办

| 现象 | 原因 | 解决 |
|---|---|---|
| 前端一次性收到所有事件 | Nginx / 代理缓冲 | `proxy_buffering off;` + `add_header X-Accel-Buffering no always;` |
| 60 秒后断开 | 无心跳或 `proxy_read_timeout` 太小 | 心跳 15s + 超时 300s |
| 收到的不是 SSE 而是 JSON | Controller 缺 `produces` | 加 `MediaType.TEXT_EVENT_STREAM_VALUE` |
| 刷新后进度卡住 | 未补发 done | `stream()` 里判断已完成状态 |
| `SseEmitter` 完成后前端拿到空响应 | `send` 后立刻 `complete` | 延迟 200ms 再 complete |
| `AsyncRequestTimeoutException` | `spring.mvc.async.request-timeout` < emitter 超时 | 调大 MVC 超时 |
| 切页面后连接不释放 | 没在 `onUnmounted` 关流 | 调 `store.closeStream()` |
| 多个标签页时进度互相覆盖 | 服务端同一 reportId 只保留一个 emitter | 设计如此（新连接顶掉旧的），可在 UI 提示 |

## 11.8 自测题

1. **为什么选 SSE 不选 WebSocket？** → 单向推送、HTTP 语义、部署简单。
2. **为什么不用原生 EventSource？** → 不能带请求头，token 会进 URL 的日志。
3. **为什么必须心跳？** → 中间设备常在空闲 30-60s 断连，注释行能重置计时。
4. **刷新页面后怎么不卡住？** → 重连时若已完成，补发 done 后延迟关闭。
5. **为什么 send 后不能立刻 complete？** → 事件可能还没 flush，前端拿到空响应。
6. **SSE 挂了怎么办？** → 重试 3 次后退化为 2s 轮询，最多 60 次。
