# 步骤 13：社区列表、筛选与投票（5 小时）

> **目标**：社区首页能按"目标岗位 / 经验年限"筛选、按"最新 / 热度"排序；帖子能赞/踩，同一人重复点同一按钮=取消，不能给自己投票。

---

## 13.1 这一步做出什么

| 场景 | 行为 |
|---|---|
| 列表默认 | 按发布时间倒序，分页 |
| 按岗位筛选 | 等值匹配 `targetPosition`（下拉选，不模糊搜） |
| 按经验筛选 | 区间 `expMin..expMax` |
| 按热度排序 | Redis ZSET 优先；Redis 挂了走 MySQL `hot_score` |
| 匿名帖 | 列表/详情不返回 userId 与真实昵称 |
| 点赞 | 首次点赞 `upCount+1`，`myVote=UP` |
| 再点一次 | 取消，`upCount-1` |
| 点赞后点踩 | 改票：`up-1, down+1` |
| 给自己的帖子投票 | 400 + `code=43007` |

---

## 13.2 为什么这样设计（面试可讲）

**① 为什么岗位筛选用等值匹配而不是 `LIKE '%Java%'`？**
`LIKE '%xx%'` 无法使用索引（前缀通配），在 10 万行帖子表上会退化为全表扫描。
而岗位是**有限枚举**（来自用户保存的 JD 标题），前端用下拉选，后端做等值匹配，`idx_post_position(status, target_position, created_at)` 能完整命中。

**② 经验年限为什么用区间，索引怎么建？**
`WHERE status=? AND years_of_experience BETWEEN ? AND ? ORDER BY created_at DESC`：
`status` 等值 + 区间列 + 排序，MySQL 只能用索引做过滤，排序会走 filesort。在万级数据下耗时可忽略。
如果要彻底消除 filesort，可把经验改成"分档枚举"（应届/1-3年/3-5年/5年+）做等值筛选 —— 这是产品与性能的取舍，本项目选择保留区间（更准确），接受小规模下的排序成本。

**③ 为什么热度用 Redis ZSET，同时又在 MySQL 存 `hot_score`？**
- **ZSET** 适合"全站热门榜"，`ZREVRANGE` 天然按分值排序，O(log N) 更新；
- 但**带筛选条件时**（岗位 + 年限）无法直接用 ZSET，只能走 MySQL 排序，所以要冗余 `hot_score` 列；
- Redis 挂了也不能让功能不可用 → MySQL 列就是兜底。

这就是"用缓存加速主路径，但主路径本身也能跑"的典型写法。

**④ 热度公式为什么带时间衰减？**

```
base = max(0, up - down) * 1.0
     + commentCount * 2.0
     + log10(viewCount + 1) * 3.0
hot  = base / (hoursSincePublish + 2) ^ 1.5
```

- 没有衰减：三年前的老帖永远压着新帖，社区会"死掉"；
- `commentCount` 权重 ×2：写评论的成本远高于点赞，是更强的质量信号；
- `viewCount` 用 `log10`：把浏览量的影响力压平，防止"刷浏览"直接冲榜；
- `+2`：防止刚发布时除零，同时给新帖一点冷启动优势；
- `^1.5`：社区产品常用的衰减曲线，比线性衰减更"快落"，比平方更温和。

**⑤ 为什么投票用"改票"而不是"多选"？**
点赞和点踩是**互斥语义**（我不可能同时觉得好和差）。所以 Service 里三种情况：
- 没投过 → 新增；
- 投了同类型 → 取消（删除）；
- 投了相反类型 → 改票（删 + 增 + 两个计数 ±1）。

用 `uk_vote(user_id, target_type, target_id, vote_type)` 保证不会重复插入。

**⑥ 为什么计数字段要存在 `post` 表上，而不用 `COUNT(*)` 实时算？**
列表页要展示每个帖子的赞数。如果用 `COUNT(*)`，一页 10 条帖子就是 10 次聚合查询（或一次 `GROUP BY`），在投票表上百万行时很慢。
冗余计数字段 + 同事务更新 = O(1) 读取。代价是要保证一致性（见 13.5）。

**⑦ 为什么不能给自己投票？**
允许自赞会让热度榜失去意义（发完自己点 10 个赞），而且对他人不公平。规则简单、实现成本低，所以直接禁止。

**⑧ 为什么匿名只在"输出层"处理？**
`post.user_id` 必须存，否则"作者能删自己的帖子""不能自赞""违规可追溯"都做不到。
匿名只是**对外不暴露**：列表/详情若 `isAnonymous=true`，返回 `{anonymous:true, nickname:"匿名用户"}`，不返回 `userId`。

### 13.4.2 匿名脱敏

```java
@Service
@RequiredArgsConstructor
public class PostQueryService {

    private final PostRepository postRepository;
    private final CommentRepository commentRepository;
    private final VoteRepository voteRepository;
    private final UserRepository userRepository;
    private final HotScoreService hotScoreService;

    @Transactional(readOnly = true)
    public PageResult<PostSummaryVO> list(PostQuery q, Long currentUserId) {
        Pageable pageable = PageRequest.of(Math.max(q.page() - 1, 0), Math.min(q.size(), 50));

        Page<Post> page;
        if ("hot".equals(q.sort())) {
            // 热度排序：先取 Redis 榜单里的 id，再按 id 批量查（Redis 不可用则回退 DB）
            var ids = hotScoreService.topIds(q.offset(), q.size());
            if (ids.isEmpty()) {
                page = postRepository.search("PUBLISHED", q.position(), q.expMin(), q.expMax(),
                        PageRequest.of(pageable.getPageNumber(), pageable.getPageSize(),
                                Sort.by(Sort.Direction.DESC, "hotScore", "createdAt")));
            } else {
                var posts = postRepository.findAllById(ids);
                var ordered = ids.stream().map(posts::stream)
                        .flatMap(s -> s.findFirst().stream()).toList();
                return PageResult.of(ordered.stream().map(this::toSummary).toList());
            }
        } else {
            page = postRepository.search("PUBLISHED", q.position(), q.expMin(), q.expMax(), pageable);
        }

        // 批量查作者，避免 N+1
        Set<Long> userIds = page.getContent().stream().map(Post::getUserId).collect(Collectors.toSet());
        Map<Long, String> nicknames = userRepository.findAllById(userIds).stream()
                .collect(Collectors.toMap(AppUser::getId, AppUser::getNickname));

        List<PostSummaryVO> vos = page.getContent().stream()
                .map(p -> toSummary(p, nicknames.get(p.getUserId()), currentUserId))
                .toList();
        return new PageResult<>(vos, page.getTotalElements(), q.page(), q.size(), page.getTotalPages());
    }

    private PostSummaryVO toSummary(Post p, String nickname, Long currentUserId) {
        boolean anonymous = Boolean.TRUE.equals(p.getIsAnonymous());
        // 作者本人视角：显示自己（便于管理），但对外仍是匿名
        boolean isOwner = currentUserId != null && currentUserId.equals(p.getUserId());

        return new PostSummaryVO(
                p.getId(),
                p.getTitle(),
                anonymous ? new AuthorVO(true, null, "匿名用户")
                          : new AuthorVO(false, p.getUserId(), nickname),
                p.getTargetPosition(),
                p.getYearsOfExperience(),
                p.getOverallScore() == null ? null : p.getOverallScore().doubleValue(),
                p.getContent(),
                p.getUpCount(), p.getDownCount(), p.getCommentCount(), p.getViewCount(),
                isOwner,
                p.getCreatedAt()
        );
    }
}
```

> **`isOwner` 判断留在服务端**：前端用这个字段决定是否显示"删除/采纳"。前端不拿到真实 userId 就无法自己判断，**匿名性由此得到保证**。

```java
@Service
@RequiredArgsConstructor
public class VoteService {

    private final VoteRepository voteRepository;
    private final PostRepository postRepository;
    private final CommentRepository commentRepository;
    private final HotScoreService hotScoreService;

    /** 帖子投票：UP / DOWN 互斥 */
    @Transactional
    public VoteResultVO votePost(Long userId, Long postId, String voteType) {
        Post post = postRepository.findByIdAndStatus(postId, "PUBLISHED")
                .orElseThrow(() -> new BizException(ErrorCode.POST_NOT_VISIBLE));
        if (post.getUserId().equals(userId)) throw new BizException(ErrorCode.SELF_VOTE_FORBIDDEN);

        String type = normalize(voteType, List.of("UP", "DOWN"));

        var existing = voteRepository.findByUserIdAndTargetTypeAndTargetId(userId, "POST", postId);
        if (existing.isPresent()) {
            Vote v = existing.get();
            if (v.getVoteType().equals(type)) {
                voteRepository.delete(v);                  // 再点一次 = 取消
                adjust(post, type, -1);
            } else {
                // 改票：反向计数 -1，正向 +1
                adjust(post, v.getVoteType(), -1);
                v.setVoteType(type);
                adjust(post, type, +1);
            }
        } else {
            Vote v = new Vote();
            v.setUserId(userId);
            v.setTargetType("POST");
            v.setTargetId(postId);
            v.setVoteType(type);
            voteRepository.save(v);
            adjust(post, type, +1);
        }

        postRepository.save(post);
        hotScoreService.update(post);                      // 更新 ZSET + hot_score

        String myVote = voteRepository.findByUserIdAndTargetTypeAndTargetId(userId, "POST", postId)
                .map(Vote::getVoteType).orElse(null);
        return new VoteResultVO(post.getUpCount(), post.getDownCount(), myVote);
    }

    private void adjust(Post p, String type, int delta) {
        if ("UP".equals(type)) p.setUpCount(Math.max(0, p.getUpCount() + delta));
        else p.setDownCount(Math.max(0, p.getDownCount() + delta));
    }

    private String normalize(String type, List<String> allowed) {
        String t = type == null ? "" : type.trim().toUpperCase();
        if (!allowed.contains(t)) throw new BizException(ErrorCode.PARAM_INVALID, "投票类型不合法");
        return t;
    }
}
```

```java
@Transactional
public VoteResultVO voteComment(Long userId, Long commentId, String voteType) {
    Comment c = commentRepository.findByIdAndStatus(commentId, "PUBLISHED")
            .orElseThrow(() -> new BizException(ErrorCode.COMMENT_NOT_FOUND));
    if (c.getUserId().equals(userId)) throw new BizException(ErrorCode.SELF_VOTE_FORBIDDEN);

    String type = normalize(voteType, List.of("UP", "USEFUL"));
    var existing = voteRepository.findByUserIdAndTargetTypeAndTargetIdAndVoteType(
            userId, "COMMENT", commentId, type);

    if (existing.isPresent()) {
        voteRepository.delete(existing.get());
        if ("UP".equals(type)) c.setLikeCount(Math.max(0, c.getLikeCount() - 1));
        else c.setUsefulCount(Math.max(0, c.getUsefulCount() - 1));
    } else {
        Vote v = new Vote();
        v.setUserId(userId); v.setTargetType("COMMENT");
        v.setTargetId(commentId); v.setVoteType(type);
        voteRepository.save(v);
        if ("UP".equals(type)) c.setLikeCount(c.getLikeCount() + 1);
        else c.setUsefulCount(c.getUsefulCount() + 1);
    }
    commentRepository.save(c);
    return new VoteResultVO(commentId, c.getLikeCount(), c.getUsefulCount());
}
```

> 评论的 `UP`（点赞）与 `USEFUL`（有用）**互不排斥**，因为 `uk_vote` 里含 `vote_type`，天然允许同时存在。

## 13.6 热度

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class HotScoreService {

    private static final String ZSET_KEY = "zset:post:hot";

    private final StringRedisTemplate redis;
    private final PostRepository postRepository;

    public double compute(Post p) {
        long hours = Duration.between(
                p.getCreatedAt().atOffset(ZoneOffset.UTC),
                LocalDateTime.now(ZoneOffset.UTC).atOffset(ZoneOffset.UTC)).toHours();

        double base = Math.max(0, p.getUpCount() - p.getDownCount()) * 1.0
                + p.getCommentCount() * 2.0
                + Math.log10(p.getViewCount() + 1) * 3.0;
        return base / Math.pow(hours + 2, 1.5);
    }

    public void update(Post p) {
        double hot = compute(p);
        p.setHotScore(hot);                                 // 兜底排序列
        try {
            redis.opsForZSet().add(ZSET_KEY, String.valueOf(p.getId()), hot);
        } catch (Exception e) {
            log.warn("hot zset update failed, postId={}", p.getId());   // 不影响主流程
        }
    }

    /** 取榜单；Redis 不可用返回空列表，调用方回退到 DB 排序 */
    public List<Long> topIds(int offset, int size) {
        try {
            var set = redis.opsForZSet().reverseRange(ZSET_KEY, offset, offset + size - 1L);
            if (set == null) return List.of();
            return set.stream().map(Long::valueOf).toList();
        } catch (Exception e) {
            return List.of();
        }
    }
}
```

```java
@Component
@RequiredArgsConstructor
@Slf4j
public class HotScoreRebuildJob {

    private final PostRepository postRepository;
    private final HotScoreService hotScoreService;

    /** 热度含时间衰减，必须周期性重算，否则老帖分数永远不变 */
    @Scheduled(cron = "0 0/10 * * * *")   // 每 10 分钟
    public void rebuild() {
        LocalDateTime since = LocalDateTime.now(ZoneOffset.UTC).minusDays(30);
        var posts = postRepository.findByStatusAndCreatedAtAfter("PUBLISHED", since);
        posts.stream().limit(2000).forEach(hotScoreService::update);
        log.debug("hot score rebuilt: {}", posts.size());
    }
}
```

## 13.7 浏览计数缓冲

```java
@Component
@RequiredArgsConstructor
public class ViewCounter {

    private static final String HASH = "stats:post:view";
    private final StringRedisTemplate redis;

    public void incr(Long postId) {
        try {
            redis.opsForHash().increment(HASH, String.valueOf(postId), 1);
        } catch (Exception ignored) { }
    }

    /** 每 5 分钟批量回写；Redis 不可用时直接更新 DB */
    @Scheduled(fixedDelay = 300_000)
    public void flush() {
        try {
            Map<Object, Object> all = redis.opsForHash().entries(HASH);
            if (all.isEmpty()) return;
            redis.delete(HASH);
            all.forEach((k, v) -> postRepository.findById(Long.valueOf(k.toString()))
                    .ifPresent(p -> {
                        p.setViewCount(p.getViewCount() + Integer.parseInt(v.toString()));
                        postRepository.save(p);
                    }));
        } catch (Exception e) {
            log.warn("view flush failed", e);
        }
    }
}
```

## 13.11 报错怎么办

| 现象 | 原因 | 解决 |
|---|---|---|
| 列表报 500 | 匿名帖返回了 null userId | `AuthorVO` 里 userId 允许为 null |
| 点赞数越点越多 | 没查到已有投票 | 检查 `findByUserIdAndTargetTypeAndTargetId` |
| 取消后计数变成负数 | 未做 `Math.max(0, ...)` | 已加 |
| 热度排序一直是空 | ZSET 没数据（定时任务没跑） | 首次发帖时会 `update`，或手动触发 rebuild |
| Redis 停掉列表 500 | 没捕获异常 | `topIds` 里 catch 返回空 list |
| 帖子详情浏览数不涨 | 只写 Redis，5 分钟后才回写 | 正常；可加 `flush` 手动触发 |
| `hot_score` 一直是 0 | 只在投票时更新 | 发帖时也要调一次 `update` |
| 匿名帖作者能删 | `isOwner` 用真实 userId 判断（服务端） | 正确行为；前端只据此显示按钮 |

## 13.12 自测题

1. **为什么岗位筛选用等值不用模糊？** → `LIKE '%x%'` 无法走索引。
2. **为什么热度要存两份（ZSET + 列）？** → ZSET 服务全站榜，列服务带筛选的排序，且互为兜底。
3. **热度为什么要时间衰减，各因子为什么这样配权？** → 防老帖霸榜；评论权重高于点赞；浏览量取 log 防刷。
4. **投票的三种状态怎么处理？** → 新增/取消/改票，靠唯一键防重复。
5. **为什么计数存在 post 表上？** → 列表页 O(1) 读取，避免每页 10 次聚合。
6. **匿名为什么只做输出层处理？** → 需要作者身份支撑"可删/防自赞/可追溯"。
