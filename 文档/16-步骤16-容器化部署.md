# 步骤 16：容器化与部署（4 小时）

> **目标**：`docker compose up -d --build` 一条命令，从零把这套系统跑起来；同时补上线上必须改的安全项。
>
> **前提**：本地已经跑通了主链路（步骤 1-15）。**不要在本地没跑通的情况下去调服务器。**

## 16.2 为什么这样设计（面试可讲）

**① 为什么用 Docker Compose 而不是"服务器上手动装 JDK/MySQL"？**
- **可复现**：镜像锁定了 JDK 版本、MySQL 版本、时区、字符集，不会出现"我本地好的、服务器不行"；
- **依赖编排**：`depends_on: condition: service_healthy` 保证后端在 MySQL 就绪后才启动，否则 Flyway 会因为连不上库而启动失败；
- **一条命令回滚**：`docker compose down` 就干净了；手动装的东西卸载起来很痛苦。

**② 为什么用多阶段构建后端镜像？**
```dockerfile
FROM maven:... AS build      ← 有 Maven + JDK
RUN mvn package
FROM eclipse-temurin:17-jre  ← 只要 JRE
COPY --from=build app.jar
```
最终镜像只有 JRE + jar（约 200MB），而不是 Maven 全家（约 700MB）。**镜像小 = 拉取快 = 部署快。**

**③ 为什么前端用 Nginx 托管而不是 `npm run dev`？**
Vite dev server 不能用于生产（无压缩、无缓存头、源码可读）。`npm run build` 出的静态文件交给 Nginx，同时由 Nginx 反向代理 `/api`，这样前后端同源，**连 CORS 都不需要配**。

**④ 为什么 Nginx 里 SSE 必须 `proxy_buffering off`？**
Nginx 默认会把上游响应攒成 4KB/8KB 的块再发。SSE 事件很小很慢，会被"攒住"直到连接关闭才一次性吐出 —— 用户看到的就是"转圈 8 秒然后瞬间完成"。
`proxy_buffering off` + `X-Accel-Buffering: no` 关掉这层缓冲。

**⑤ 为什么数据库用 volume 而不是"容器里存"？**
容器一删就没了。`mysql-data:/var/lib/mysql` 把数据目录挂到宿主机卷上，`docker compose down` 不会丢数据（`down -v` 才会，这是危险操作）。

**⑥ 为什么端口要映射，而且要注意冲突？**
你本机 3306 已被系统 MySQL 占用。如果 compose 也用 `3306:3306`，会报 `port is already allocated`。
方案：本地开发不用 compose 的 mysql（用现有 MySQL）；或者把映射改成 `3307:3306`。

**⑦ 上线必须改的三样东西**
- `JWT_SECRET`：默认值只适合本地，线上必须换成 ≥32 字节随机串（否则谁都能伪造 token）；
- `DB_PASSWORD`：不能是 123456；
- `AI_ENABLED`：演示时再打开，注意额度。

## 16.3 后端 Dockerfile

`BackEnd/Dockerfile`：

```dockerfile
# ---------- 构建阶段 ----------
FROM maven:3.9-eclipse-temurin-17 AS build
WORKDIR /app
COPY pom.xml .
RUN mvn -B -q dependency:go-offline
COPY src ./src
RUN mvn -B -q clean package -DskipTests

# ---------- 运行阶段 ----------
FROM eclipse-temurin:17-jre
WORKDIR /app
RUN apt-get update && apt-get install -y --no-install-recommends wget \
    && rm -rf /var/lib/apt/lists/*
COPY --from=build /app/target/*.jar app.jar
ENV JAVA_OPTS="-Xms256m -Xmx512m -Duser.timezone=UTC"
EXPOSE 8080
ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar /app/app.jar"]
```

`BackEnd/.dockerignore`：

```
target/
.idea/
*.iml
.mvn/
src/test/
```

> **`-DskipTests`**：CI 里跑测试，构建镜像时跳过（否则每次构建都慢 1 分钟）。如果想让镜像自带质量门禁，可以去掉，但要保证测试不依赖外部服务。

## 16.4 前端 Dockerfile（已有）

`Front/Dockerfile`：

```dockerfile
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:1.27-alpine
COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
```

`Front/nginx.conf`（关键部分）：

```nginx
server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;

    gzip on;
    gzip_min_length 1024;
    gzip_types text/plain text/css application/javascript application/json;

    location / {
        try_files $uri $uri/ /index.html;     # SPA fallback
    }

    location /api/ {
        proxy_pass http://backend:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Connection "";

        # SSE 必须：关闭缓冲、拉长超时
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        add_header X-Accel-Buffering no always;
    }
}
```

## 16.5 `docker-compose.yml`（项目根目录）

```yaml
services:
  mysql:
    image: mysql:8.0
    container_name: jianli-mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_PASSWORD:-123456}
      MYSQL_DATABASE: resume_ai
      TZ: UTC
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_0900_ai_ci
      - --default-time-zone=+00:00
    ports:
      - "3307:3306"                 # 本地 3306 已被系统 MySQL 占用
    volumes:
      - mysql-data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-p${DB_PASSWORD:-123456}"]
      interval: 10s
      timeout: 5s
      retries: 10

  redis:
    image: redis:7-alpine
    container_name: jianli-redis
    restart: unless-stopped
    command: ["redis-server", "--appendonly", "no", "--maxmemory", "256mb", "--maxmemory-policy", "volatile-lru"]
    ports:
      - "6380:6379"                 # 避免和本地 Redis 6379 冲突
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 3s
      retries: 5

  backend:
    build: ./BackEnd
    container_name: jianli-backend
    restart: unless-stopped
    depends_on:
      mysql:
        condition: service_healthy
      redis:
        condition: service_healthy
    environment:
      SPRING_PROFILES_ACTIVE: docker
      DB_HOST: mysql
      DB_PORT: 3306
      DB_PASSWORD: ${DB_PASSWORD:-123456}
      REDIS_HOST: redis
      REDIS_PORT: 6379
      JWT_SECRET: ${JWT_SECRET:-dev-only-change-me-please-32bytes-min!!}
      AI_ENABLED: ${AI_ENABLED:-false}
      DASHSCOPE_API_KEY: ${DASHSCOPE_API_KEY:-}
    ports:
      - "8080:8080"
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://localhost:8080/actuator/health"]
      interval: 15s
      timeout: 5s
      retries: 10
      start_period: 60s

  frontend:
    build: ./Front
    container_name: jianli-frontend
    restart: unless-stopped
    depends_on:
      backend:
        condition: service_started
    ports:
      - "80:80"

volumes:
  mysql-data:
```

`.env`（项目根目录，**不要提交**）：

```env
DB_PASSWORD=change_me_strong_password
JWT_SECRET=replace_with_a_random_32_bytes_or_longer_string
AI_ENABLED=false
DASHSCOPE_API_KEY=
```

> ```bash
> openssl rand -base64 32
> ```

## 16.7 上服务器

```bash
# 服务器（Linux）装 Docker
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
docker compose version

# 拉代码
git clone <你的仓库> /opt/jianli && cd /opt/jianli

# 配置
cp .env.example .env
vim .env      # 改 DB_PASSWORD / JWT_SECRET / CORS / AI

# 启动
docker compose up -d --build
docker compose ps
docker compose logs -f backend
```

**上线前检查清单**

| 项 | 要求 |
|---|---|
| `JWT_SECRET` | ≥32 字节随机串，**不是默认值** |
| `DB_PASSWORD` | 强密码，且 3307/6380 端口**不要**对公网暴露（删掉 ports 映射，只保留容器内网络） |
| `CORS_ORIGINS` | 改成真实域名 |
| `AI_ENABLED` | 需要时打开，注意额度 |
| HTTPS | 建议在前面加一层 Caddy 或 Certbot，SSE 在 HTTPS 下同样可用 |
| 日志 | `docker compose logs --tail=200 backend`，或挂 volume 持久化 |
| 备份 | 至少定时 `mysqldump`（本项目不做备份系统，但你要知道这是缺口） |

**生产环境建议删掉端口映射**（只保留 frontend 的 80）：

```yaml
  mysql:
    # ports: 生产不需要对外暴露
  redis:
    # ports: 同上
  backend:
    # ports: 由 Nginx 反代，不需要对外暴露
```

## 16.8 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `port is already allocated` | 3306/6379 被本地服务占用 | 已改成 3307/6380；或停掉本地服务 |
| backend 一直 unhealthy | MySQL 还没就绪 / Flyway 失败 | `docker compose logs backend` 看具体错误 |
| 前端 502 | backend 还没起来 | `depends_on` 只保证启动顺序，不保证就绪；等 60s |
| 页面刷新 404 | 缺 SPA fallback | `try_files ... /index.html` |
| SSE 一次性输出 | Nginx 缓冲 | `proxy_buffering off` |
| 中文乱码 | MySQL 容器字符集 | `--character-set-server=utf8mb4` |
| 时间差 8 小时 | 容器时区 + JDBC 时区不一致 | `TZ=UTC` + 连接串 `connectionTimeZone=UTC` + Jackson `GMT+8` |
| 镜像拉取超时 | 网络 | Docker Desktop → Settings → Docker Engine 加 registry-mirrors |
| `docker compose` 命令不存在 | 只装了旧版 docker-compose | 装 Docker Compose v2（`docker compose` 带空格） |
| 改了代码但没生效 | 用了缓存层 | `docker compose up -d --build --no-cache backend` |

## 16.9 自测题

1. **为什么 compose 能解决"本地好服务器不好"？** → 镜像锁定运行时版本、字符集、时区；依赖健康检查保证启动顺序。
2. **多阶段构建的好处？** → 运行镜像只含 JRE + jar，体积和攻击面都更小。
3. **为什么用 Nginx 托管前端？** → 生产不能用 dev server；顺便做 `/api` 反向代理，前后端同源免 CORS。
4. **SSE 在 Nginx 后面为什么要特殊配置？** → 默认缓冲会攒住小事件，用户看不到进度。
5. **数据为什么挂 volume？** → 容器可抛弃，数据要持久。
6. **上线必须改什么？** → JWT_SECRET、DB_PASSWORD、CORS、AI 开关，以及不要暴露 DB/Redis 端口。
