# AI 辅助简历分析与社区互评平台 · 开发手册

> **按敲代码的顺序写**。不是功能说明书，而是"今天打开 IDEA 先写哪个类、写完敲什么命令验证它对不对"。
>
> 每一步都是四段：**要写什么 → 为什么这么写（面试怎么说）→ 怎么验证 → 报错怎么办**。
> **验证不通过就别进下一步** —— 这个项目最容易崩的地方是"写了 20 个类一起启动，报错不知道从哪找"。

---

## 一、项目一句话

粘贴**简历文本** + **目标岗位 JD** → JD 与简历结构化解析 → **ATS 风格匹配评分（程序算分）** → 关键词命中/缺失 + 密度 → 按板块的改进建议 → **逐条改写优化** → 多版本管理与对比；分析结果**脱敏后可发布到社区**，他人评论/投票，作者可**采纳建议并生成新版本**，再分析看分数变化。

**四个贯穿全项目的主张（面试必讲）：**

| 主张 | 一句话理由 |
|---|---|
| **分数由程序算，AI 只做抽取** | 可复现、可解释、可测试、抗注入；模型升级不让历史分数作废 |
| **AI 是可关的增强项** | `AI_ENABLED=false` 时全链路可用（规则兜底），面试预演题模块整体隐藏 |
| **Redis 只存可重建数据** | 缓存/登录态/热度/限流放 Redis；主数据与审计记录只在 MySQL |
| **发布前强制 PII 审核，规则为主** | 二元决策要确定性和低延迟；且不能把身份证发给第三方大模型 |

## 二、怎么用这套文档

```
打开 IDE
  ↓
看「步骤 N」第 1 节：这一步做出什么
  ↓
按第 3 节的文件清单在对应包里 new 类（包已建好）
  ↓
按第 4 节写代码（给了骨架与关键行，注释自己补）
  ↓
按第 5 节验证（curl / 浏览器 / MySQL），红了查第 6 节
  ↓
绿了 → 在进度表打勾 → 下一步
```

**每一步的通过标准**：`mvn compile` 无错 + 该步第 5 节验证命令输出符合预期。

## 六、三个启动脚本

| 双击 | 干什么 | 验证 |
|---|---|---|
| `start-redis.bat` | 起 Redis（6379） | `tools\Redis-x64-5.0.14.1\redis-cli.exe ping` → `PONG` |
| `start-backend.bat` | 起后端（8080） | `http://localhost:8080/actuator/health` |
| `start-front.bat` | 起前端（5173） | `http://localhost:5173` |

> `start-backend.bat` 里写死了 `JAVA_HOME=D:\7.Environment\jdk-17.0.12` —— 你系统默认的 `java` 指向一个损坏的 java8 目录（跑 `java -version` 会报 `could not open ... jvm.cfg`）。**不要直接敲 `mvn`**。

## 七、参考了哪些同类产品

| 参考对象 | 借鉴了什么 | 我们没做的 |
|---|---|---|
| `getresumeiq.com/ats-resume-checker` | 0-100 匹配分 + `scoreBreakdown` + `keywordDensity` + 按板块的 `{section, originalText, issue, suggestion}` 反馈 + 一键优化与前后对比 + 扫描历史 | Plus 订阅、模板/PDF 导出、PDF/DOCX 上传、求职自动化投递（见 README 第十节） |

**我们刻意做得不一样的地方：**
1. **分数不让 AI 出**（同类产品多数直接让模型给分）；
2. **改写逐条采纳**，不整篇生成 —— 从机制上防编造；
3. **社区互评 + 采纳回写版本**，同类产品是纯工具、无社区；
4. **发布前 PII 审核**，把"分享简历"的风险也管住。

这四条是面试里最能体现差异化的点。
