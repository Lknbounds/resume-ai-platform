**为什么按业务分包，而不是 controller/service/dao 三大包？**
改"社区"功能时只动 `community` 一个包；跨模块依赖显式可见（`community` 依赖 `analysis` 读报告快照）。单体项目里这种组织方式后期最好维护，面试时也能说清"要拆微服务就按这几个包拆"。

## 0.4 分层与命名约定（写代码时严格遵守）

| 层 | 类名后缀 | 职责 | 禁止 |
|---|---|---|---|
| Controller | `XxxController` | 收参、`@Valid` 校验、调 Service、返回 `ApiResponse` | 写业务逻辑、直接注入 Repository |
| Service | `XxxService` | 业务规则、事务边界、**归属校验**、编排 | 返回 Entity（对外一律 VO） |
| Repository | `XxxRepository` | Spring Data JPA 接口 | 写业务逻辑 |
| Entity | 表名转帕斯卡（`app_user` → `AppUser`） | 字段映射、`@PrePersist` | 业务方法 |
| DTO | 请求 `XxxRequest`，响应 `XxxVO` | 只装数据 | 复用 Entity 当请求体 |

依赖方向：`Controller → Service → Repository → Entity`，**永不反向**。

命名对照：

| 位置 | 风格 | 例子 |
|---|---|---|
| 包 / 类 | 小写点分 / 帕斯卡 | `com.jianli.analysis.calculator.ScoreCalculator` |
| 方法 / 变量 | 驼峰 | `calculateScore` |
| 数据库表 / 列 | 下划线 | `analysis_report`、`overall_score` |
| JSON 字段 | 驼峰 | `overallScore` |

## 0.5 每一步怎么验证（统一方法）

### ① 编译过了吗

```bash
cd E:\简历评价项目\BackEnd
# 用 IDEA 的 Maven 面板，或双击根目录 start-backend.bat 让它自己编译
```
最快判断：IDEA 里没有红色波浪线 + `mvn compile` 无 ERROR。

### ② 接口对不对（用 curl，不用 Postman 也行）

Windows 的 Git Bash 里可以直接用下面的模板（注意：**单引号包 JSON**）：

```bash
# 健康检查
curl -s http://localhost:8080/actuator/health

# 需要登录的接口（先登录拿 token）
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"Passw0rd1"}' \
  | python -c "import sys,json;print(json.load(sys.stdin)['data']['accessToken'])")

curl -s http://localhost:8080/api/users/me -H "Authorization: Bearer $TOKEN"
```

> 没有 python 也可以直接复制返回里的 token 手动粘进去。

**判断标准**：看 `code`。`code=0` 是成功，非 0 查 [附A 错误码表](附A-错误码与接口总表.md)。

### ③ 数据进库了吗

Git Bash 里：

```bash
M="/d/7.Environment/Mysql/MySQL Server 8.0/bin/mysql.exe"
"$M" -uroot -p123456 --default-character-set=utf8mb4 resume_ai \
  -e "SELECT id,username,nickname,created_at FROM app_user ORDER BY id DESC LIMIT 5;"
```

不想敲命令就用 Navicat / DBeaver 连上去看（主机 `localhost`、端口 3306、用户 `root`、密码 `123456`、库 `resume_ai`）。

### ④ 前端页面对不对

浏览器 F12 → Network：
- 请求头里有没有 `Authorization: Bearer xxx`；
- 响应 `code` 是不是 0；
- 失败时看 Console 有没有 CORS / 401。

## 0.7 数据库长什么样（13 张表速览）

完整 DDL 在 `BackEnd/src/main/resources/db/migration/V1__init.sql`，这里只给你**关系地图**，后面每一步会细讲用到的那几张：

```
app_user ──┬── resume ── resume_version ──┐
           ├── job_description ───────────┤
           │                              ├── analysis_report ── analysis_suggestion
           │                              │        │             └─ resume_rewrite
           │                              │        └── post ── comment ── comment(自关联两级)
           ├── privacy_review ────────────┘              └── vote（多态：POST/COMMENT）
           └── interview_question_set ── interview_question
```

| 表 | 一句话 | 哪一步用到 |
|---|---|---|
| `app_user` | 账号 | 步骤 2、3 |
| `resume` / `resume_version` | 简历主体 / 不可变内容版本 | 步骤 5 |
| `job_description` | JD 原文 + 解析结果 | 步骤 7 |
| `analysis_report` | 一次分析的结论（分数、维度、快照） | 步骤 8、9 |
| `analysis_suggestion` / `resume_rewrite` | 板块建议 / AI 重写片段 | 步骤 9、10 |
| `privacy_review` | 每次审核的结论（**不存原文**） | 步骤 12 |
| `post` | 社区帖子（含简历与报告快照） | 步骤 12 |
| `comment` / `vote` | 评论（两级）/ 投票（多态） | 步骤 13、14 |
| `interview_question_set` / `interview_question` | 面试题批次 / 题目 | 步骤 15 |

**表结构一次设计到位，实体类随模块逐步补齐** —— 这是刻意的：DDL 用 Flyway 管理、JPA 用 `ddl-auto=validate`，这样"表改了代码没改"会在启动时立刻爆炸，而不是上线后才发现。

## 0.9 写在最后：这套文档的"为什么"怎么用到面试里

每个步骤文档的第 2 节都叫 **「为什么这样设计」**，里面是"结论 → 理由 → 取舍"三段式。面试被追问时，你要说的正是这一节：

- 不要背原理，"我把 X 换成了 Y 因为 Z 场景下会出问题"才是面试官想听的；
- 每次做一个取舍，就在旁边写一行注释记下原因（比如 `// 用 REQUIRES_NEW：拒绝记录不能被外层事务回滚`），面试前翻注释就能回忆起来；
- [附C-面试问答](附C-面试问答.md) 是这些理由的浓缩版，共 16 题。
