## 二、热度公式

```
base = max(0, 赞 - 踩) × 1.0
     + 评论数 × 2.0
     + log10(浏览数 + 1) × 3.0

hot = base / (发布至今小时数 + 2) ^ 1.5
```

**为什么这样配：**

| 因子 | 权重 | 理由 |
|---|---|---|
| 赞 - 踩 | ×1 | 核心质量信号 |
| 评论 | **×2** | 写评论成本远高于点赞，是更强信号 |
| log10(浏览) | ×3 | 用 log 压平，防止"刷浏览量"主导热度 |
| `(h+2)^1.5` | 分母 | 时间衰减 —— 不衰减老帖永远霸榜；1.5 次方是快慢平衡点；+2 防刚发布时除零 |

**算例验证**（插完演示数据后 `GET /api/hot/score/{postId}`）：

```
Bob 的帖子：5 赞 4 评论 2380 浏览，3 天前发
  base = 5×1 + 4×2 + log10(2381)×3 = 5 + 8 + 10.1 = 23.1
  hot  = 23.1 / (72+2)^1.5 = 23.1 / 637 = 0.036

Alice 的帖子：2 赞 3 评论 1206 浏览，1 天前发
  base = 2 + 6 + log10(1207)×3 = 2 + 6 + 9.2 = 17.2
  hot  = 17.2 / (24+2)^1.5 = 17.2 / 132.6 = 0.13
```

> ★ 注意：Alice（1 天前）**高于** Bob（3 天前）—— 这就是时间衰减的效果。
> 虽然 Bob 数据更好，但衰减让他沉下去了。

## 五、关键设计点（面试可讲）

### 1. 为什么 ZSET 和 MySQL 列各存一份？

| 存储 | 服务什么 |
|---|---|
| Redis ZSET | **全站热门榜**（无筛选）—— `ZREVRANGE` 一次拿到排序结果 |
| MySQL `hot_score` 列 | **带筛选的排序**（岗位/年限）—— ZSET 里没有这些字段，做不了筛选 |

两处用**同一个 `compute()`**，保证分数一致。否则会出现"热度榜第 1 名在筛选列表里排第 5"。

### 2. 为什么定时重建？

- **时间衰减必须重算**：`hours` 随时间增长，即使零互动，热度也会变
- **Redis 重启自愈**：ZSET 清空后能从 MySQL 恢复
- **清理无效数据**：已删除/超 30 天的帖子

### 3. Redis 挂了会怎样？

| 功能 | 降级行为 |
|---|---|
| 热度榜 | 回退 MySQL `ORDER BY hot_score` |
| 投票 | 数据库照常更新，ZSET 写失败只打 WARN |
| 定时任务 | catch 异常，下次调度重试 |

`RedisSafe` 把"Redis 挂了"收口成一个类 —— 业务代码不用写 try-catch。

### 4. 为什么用 log10 压缩浏览量？

1000 浏览 vs 10 赞，直接相加会让浏览量完全主导（等于鼓励标题党）。
`log10(1001)=3`、`log10(10001)=4` —— 差 10 倍浏览只多 1 分。

### 5. 为什么按 id 查完还要重排？

```java
List<Post> posts = postRepository.findAllById(ids);   // 按主键升序，不是传入顺序
```

★ 如果直接用 `posts` 的顺序，热度榜就变成了"按 id 排序"—— 有数据但顺序错。必须用 `ids` 的顺序重新组装。

### 6. 零互动的帖子热度是 0，正常吗？

正常。`base = 0` → `hot = 0`。
即使刚发布（分母很小），0 除以任何数还是 0。
**没有互动就没有热度**，这是合理的 —— 榜单不是"最新列表"。

## 六、已知的简化

| 项 | 现状 | 如果要更严谨 |
|---|---|---|
| 热度榜 total | 用 ZSET 的 `zCard`（近似值） | 需要精确时查 MySQL count |
| 浏览数 | 直接 UPDATE（没走 Redis 缓冲） | 文档里设计了 `postViewBuffer()`，高并发时再启用 |
| 重建上限 | 2000 个帖子 | 超出会打 WARN，可调 `MAX_REBUILD` |
| `/api/hot/**` 权限 | 仅需登录 | 上线应挪到 `/api/admin/**` + ROLE_ADMIN（但本项目不做管理员后台） |
| 排名角标 | 只在前端按页码推算 | 后端已有 `rank()` 方法，需要精确排名可接入 |
