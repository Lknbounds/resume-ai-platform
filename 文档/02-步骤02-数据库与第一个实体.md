# 步骤 02：数据库接入与第一个实体（2 小时）

> **目标**：应用启动时 JPA 自动校验"Java 实体 ↔ MySQL 表结构"是否一致，能通过 `UserRepository` 往 `app_user` 写一条并读回来。
>
> **这一步很关键**：它是"表结构永远和代码一致"的保障机制。后面 12 张表每加一张，你都照这个套路写实体，写错一个列名启动就会报错，而不是等运行时才发现。

---

## 2.1 这一步做出什么

1. 启动日志里出现 Flyway 的 `Current version of schema "resume_ai": 1`（或 `Schema "resume_ai" is up to date`）；
2. 应用正常启动 —— 说明 Hibernate 的 `validate` 通过了，即 **`AppUser` 实体和 `app_user` 表完全对得上**；
3. 跑一个测试，往 `app_user` 插一条再查出来；
4. `SELECT * FROM app_user` 能看到这条数据；
5. 故意把实体里某个 `@Column(name=...)` 改错一个字母，重启后**应用启动失败并报 `Schema-validation: missing column`** —— 你要亲眼看到一次这个错误，才知道它的价值。

---

## 2.2 为什么这样设计（面试可讲）

**① 为什么用 Flyway 管表结构，而不是 `ddl-auto: update`？**
`update` 只做"加列"，**从不删列、从不改类型、也从不回滚**。开发时很方便，但一旦上线：你在实体里把 `varchar(32)` 改成 `varchar(64)`，Hibernate 可能不报错也不改，线上就悄悄不一致了。
Flyway 是"SQL 脚本 + 版本号 + 执行记录"，每一步变更都有文件、有版本、可回放、可审计。`V1__init.sql` 建 13 张表，以后加字段写 `V2__add_xxx.sql`，永远不会"不知道线上是什么结构"。

**② 为什么还要 `ddl-auto: validate`？**
Flyway 保证"库里有这些表"，但保证不了"Java 实体映射对了"。`validate` 在启动时逐列比对，**列名写错一个字母就启动失败** —— 把运行时的 NPE / SQL 报错提前到启动阶段。这两个配合才是完整闭环：Flyway 管 DDL，validate 管 ORM 映射。

**③ 为什么表结构一次建 13 张，实体却分步写？**
建表是"设计决策"，改一次要写迁移脚本、考虑历史数据，代价高，所以开工时一次想清楚；实体是"代码实现"，跟着功能走最自然。
配合 `validate`，这个策略很安全：还没写实体的表不会被校验，已写的表一定对得上。

**④ 实体为什么用 `@Getter @Setter` 而不是 `@Data`？**
- `@Data` 会生成 `toString()`，把所有字段打印出来 —— 包括 `passwordHash`，一旦有人 `log.info("user={}", user)`，密码哈希就进了日志。**这是真实的泄露途径**。
- `@Data` 生成的 `equals/hashCode` 用全部字段，JPA 实体在 `Set` 里、或在懒加载代理时容易出怪问题。
- 实体应该是"贫血"的：只装字段 + 生命周期回调，不写业务方法。业务逻辑放 Service。

**⑤ 时间字段为什么统一用 `LocalDateTime` + UTC？**
跨时区/夏令时的问题用 `Instant` 最严谨，但对这个项目来说，统一"**存 UTC、展示转东八区**"已经足够，而且 `DATETIME(3)` 读写直观、Navicat 里看得懂。
关键是**统一**：连接串里 `connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true`（`application.yml` 已配），实体里用 `LocalDateTime.now(ZoneOffset.UTC)`，展示层转 GMT+8。三者只要有一处忘了，就会出现"差 8 小时"的经典 bug。

**⑥ ID 为什么用自增 `BIGINT` 而不是 UUID？**
InnoDB 的聚簇索引按主键顺序存放数据，自增主键是顺序追加，写入快、索引小、页分裂少；UUID 随机分布会导致频繁页分裂，还占 16 字节。本项目单库单表，数据量到不了需要全局唯一 ID 的规模，自增更合适。

## 2.4 逐个文件怎么写

### 2.4.1 对照表结构

先看一眼要映射的表（`V1__init.sql` 里的定义）：

```sql
CREATE TABLE `app_user` (
  `id`                  BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `username`            VARCHAR(32)     NOT NULL,
  `password_hash`       VARCHAR(100)    NOT NULL,
  `nickname`            VARCHAR(32)     NOT NULL,
  `target_position`     VARCHAR(64)     DEFAULT NULL,
  `years_of_experience` TINYINT UNSIGNED NOT NULL DEFAULT 0,
  `created_at`          DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  `updated_at`          DATETIME(3)     NOT NULL ... ON UPDATE CURRENT_TIMESTAMP(3),
  `last_login_at`       DATETIME(3)     DEFAULT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_username` (`username`)
);
```

### 2.4.2 实体

```java
package com.jianli.user.entity;

import jakarta.persistence.*;
import lombok.Getter;
import lombok.NoArgsConstructor;
import lombok.Setter;

import java.time.LocalDateTime;
import java.time.ZoneOffset;

@Entity
@Table(name = "app_user")
@Getter
@Setter
@NoArgsConstructor
public class AppUser {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    /** 登录名，唯一 */
    @Column(nullable = false, length = 32, unique = true)
    private String username;

    /** BCrypt 哈希，绝不返回给前端 */
    @Column(name = "password_hash", nullable = false, length = 100)
    private String passwordHash;

    @Column(nullable = false, length = 32)
    private String nickname;

    @Column(name = "target_position", length = 64)
    private String targetPosition;

    /** TINYINT UNSIGNED → Integer */
    @Column(name = "years_of_experience", nullable = false)
    private Integer yearsOfExperience;

    @Column(name = "created_at", nullable = false, updatable = false)
    private LocalDateTime createdAt;

    @Column(name = "updated_at", nullable = false)
    private LocalDateTime updatedAt;

    @Column(name = "last_login_at")
    private LocalDateTime lastLoginAt;

    @PrePersist
    void onCreate() {
        LocalDateTime now = LocalDateTime.now(ZoneOffset.UTC);
        if (createdAt == null) createdAt = now;
        updatedAt = now;
        if (yearsOfExperience == null) yearsOfExperience = 0;
    }

    @PreUpdate
    void onUpdate() {
        updatedAt = LocalDateTime.now(ZoneOffset.UTC);
    }
}
```

**注意几个细节（都是踩过的坑）：**

- `@Column(name = "...")` 只写**数据库里与字段名不同**的那些（`password_hash`、`target_position`…）。同名的不写，少一处就少一个错处。
- 字段名用驼峰，值类型用包装类 `Integer` 而不是 `int`：`int` 默认 0，无法表达"未设置"，且 `validate` 对基本类型兼容性差。
- `created_at` 加 `updatable = false`：插入后就不该再被 UPDATE 碰到。
- 数据库虽然有 `DEFAULT CURRENT_TIMESTAMP`，但 JPA 插入时会显式写这些字段，所以 `@PrePersist` 里必须赋值，否则插入 `null` 直接违反 `NOT NULL`。

### 2.4.3 Repository

```java
package com.jianli.user.repository;

import com.jianli.user.entity.AppUser;
import org.springframework.data.jpa.repository.JpaRepository;

import java.util.Optional;

public interface UserRepository extends JpaRepository<AppUser, Long> {

    Optional<AppUser> findByUsername(String username);

    boolean existsByUsername(String username);
}
```

> **方法名即查询**：`findByUsername` 会被 Spring Data 解析成 `WHERE username = ?`。不用写 SQL。
> 为什么需要 `existsByUsername`：注册时判重，比 `findByUsername().isPresent()` 少查一列（内部生成 `SELECT 1 ... LIMIT 1`）。

### 2.4.4 统一时间格式

`application.yml` 里的 `spring.jackson.date-format` **只对 `java.util.Date` 生效**，`LocalDateTime` 默认输出 `2026-11-18T16:00:00`（带 `T`）。要输出 `2026-11-18 16:00:00`，加这个配置类：

```java
package com.jianli.config;

import com.fasterxml.jackson.datatype.jsr310.deser.LocalDateTimeDeserializer;
import com.fasterxml.jackson.datatype.jsr310.ser.LocalDateTimeSerializer;
import org.springframework.boot.autoconfigure.jackson.Jackson2ObjectMapperBuilderCustomizer;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

import java.time.format.DateTimeFormatter;

@Configuration
public class JacksonConfig {

    private static final DateTimeFormatter FMT =
            DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");

    @Bean
    public Jackson2ObjectMapperBuilderCustomizer localDateTimeCustomizer() {
        return builder -> builder
                .serializers(new LocalDateTimeSerializer(FMT))
                .deserializers(new LocalDateTimeDeserializer(FMT));
    }
}
```

### 2.4.5 测试（第一次写单测）

`BackEnd/src/test/java/com/jianli/user/UserRepositoryTest.java`：

```java
package com.jianli.user.repository;

import com.jianli.user.entity.AppUser;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.transaction.annotation.Transactional;

import static org.assertj.core.api.Assertions.assertThat;

@SpringBootTest
@Transactional          // 测试结束自动回滚，不污染数据库
class UserRepositoryTest {

    @Autowired
    private UserRepository userRepository;

    @Test
    void 保存后能按用户名查到() {
        AppUser u = new AppUser();
        u.setUsername("test_" + System.currentTimeMillis());
        u.setPasswordHash("$2a$10$fakehashforunitestonly");
        u.setNickname("测试用户");
        u.setTargetPosition("Java 后端开发");
        u.setYearsOfExperience(3);

        AppUser saved = userRepository.save(u);

        assertThat(saved.getId()).isNotNull();
        assertThat(saved.getCreatedAt()).isNotNull();

        var found = userRepository.findByUsername(saved.getUsername());
        assertThat(found).isPresent();
        assertThat(found.get().getNickname()).isEqualTo("测试用户");
        assertThat(found.get().getYearsOfExperience()).isEqualTo(3);
    }

    @Test
    void 用户名判重() {
        AppUser u = new AppUser();
        u.setUsername("dup_" + System.currentTimeMillis());
        u.setPasswordHash("x");
        u.setNickname("n");
        u.setYearsOfExperience(0);
        userRepository.save(u);

        assertThat(userRepository.existsByUsername(u.getUsername())).isTrue();
        assertThat(userRepository.existsByUsername("绝不存在的名字")).isFalse();
    }
}
```

> `@Transactional` 在测试类上是"**跑完自动回滚**"，不是真实提交。所以不会在你的库里留下垃圾数据，但测试里读得到 —— 这是 Spring 测试的标准做法。
> 方法名用中文是允许的（Java 标识符支持 Unicode），方便你一眼看出测的是什么；不喜欢就换成英文。

## 2.6 报错怎么办

| 现象 | 原因 | 解决 |
|---|---|---|
| `Schema-validation: missing table [app_user]` | 表没建 | 跑 `init-db.bat` |
| `Schema-validation: wrong column type` | 实体类型和表不符（如 `Integer` vs `BIGINT`） | 对照 DDL 改实体类型 |
| `Schema-validation: missing column` | `@Column(name=...)` 写错 | 逐字对照 DDL |
| Flyway 报 `Validate failed: Migration checksum mismatch` | 改了已执行过的 `V1__init.sql` | 本地 `init-db.bat` 重置；以后改了要新增 `V2__xxx.sql` 而不是改 V1 |
| `Access denied for user 'root'` | 密码不对 | 改 `application.yml` 的 `DB_PASSWORD` 或设环境变量 |
| `Public Key Retrieval is not allowed` | MySQL 8 认证插件 | 连接串已带 `allowPublicKeyRetrieval=true`，确认没删 |
| 测试类启动很慢（10 秒+） | `@SpringBootTest` 会起完整上下文 | 正常；可以用 `@DataJpaTest` 但需要额外配置数据源，先不折腾 |
| 时间少 8 小时 | 时区没统一 | 确认连接串有 `connectionTimeZone=UTC`，实体用 `LocalDateTime.now(ZoneOffset.UTC)` |

## 2.7 自测题

1. **Flyway 和 `ddl-auto=validate` 各管什么？为什么两个都要？** → Flyway 管"库里有正确的表"，validate 管"代码映射对得上"。
2. **实体为什么不用 `@Data`？** → `toString` 会打印密码哈希，`equals/hashCode` 用全字段在 JPA 代理下容易出错。
3. **`@PrePersist` 和数据库的 `DEFAULT CURRENT_TIMESTAMP` 重复了吗？** → 不重复。JPA 插入时会显式带上该字段（值为 null），数据库默认值不生效，所以必须在 `@PrePersist` 里赋值。
4. **`@Transactional` 在测试类上是什么效果？** → 每个测试方法结束后回滚，不污染数据库。
5. **为什么主键用自增 BIGINT？** → InnoDB 聚簇索引顺序写入、索引小、页分裂少；UUID 随机会导致写入放大。
