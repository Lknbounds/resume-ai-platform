# 步骤 14：评论、有用投票与采纳（6 小时）

> **目标**：评论能按简历板块归类、支持两级回复（第三级被拒）；评论可投"点赞/有用"；帖子作者能把某条评论标为"已采纳"，并可据此生成新的简历版本，然后重新分析看分数变化。
>
> **"采纳 → 新版本 → 分数变化"是社区闭环的关键**，也是面试最容易讲出产品思考的地方。

---

## 14.1 这一步做出什么

| 场景 | 行为 |
|---|---|
| 顶层评论 | `parentId=null`，`section` 可选（默认 OTHER） |
| 回复 | `parentId` 指向顶层，`rootId` 指向同一条 |
| 回复回复 | 400 + `code=43005`（只支持两级） |
| 按板块筛选 | `?section=PROJECT` 只返回该板块顶层评论 |
| 点赞 / 有用 | 两个独立计数，可同时投 |
| 采纳 | 只有**帖子作者**能采纳；不能采纳自己的评论 |
| 采纳并生成版本 | 在帖子来源简历上新增 `ADOPT_COMMENT` 版本，回写 `adoptedVersionId` |
| 评论含手机号 | 422 + `43002`（同样审核） |

---

## 14.2 为什么这样设计（面试可讲）

**① 为什么只做两级，不做无限嵌套？**
三级以上的回复在 UI 上极难阅读（缩进吃掉半个屏幕），实际讨论中也很少有人跟进到第三层。而且无限嵌套要么用递归查询（MySQL 8 需 CTE），要么在应用层多次查询。
固定两级（顶层 + 回复）的实现：**一次查询取全部，内存里按 `rootId` 分组**，代码简单、查询恒定 1 次。
第三级直接拒绝并提示"请回复到原评论下"，比默默折叠更好。

**② 为什么评论要"按板块归类"？**
这是本项目的差异化设计：简历是分板块的（技能/经历/项目/教育），建议也应该按板块提。
好处：
- 作者能按板块看"哪块被吐槽最多"；
- 采纳时能直接对应到具体板块（生成新版本时带上 `section`）；
- 与自己分析报告里的"板块建议"形成呼应。

**③ 为什么用 `parent_id` + `root_id` 两个字段，而不是只用一个？**
只存 `parent_id`（指向被回复的评论）时，要查"某条顶层评论下的所有回复"必须递归或自连接。
加 `root_id` 后：`WHERE post_id=? AND root_id=?` 一次取全，或者 `WHERE post_id=?` 一次取整个帖子的评论再内存分组。
冗余一个字段，换来查询简单 —— 这是"读多写少"场景下典型的反范式取舍。

**④ 为什么"采纳"要单独一个动作，而不是随便标记？**
因为采纳是**给评论者的正反馈**，也是对后来者的信号（"这条建议真的有用"）。它同时：
- 让作者产生"改简历"的行动，形成闭环；
- 让优质评论者获得可见的认可（`adopted=true` + 采纳数）；
- 让帖子本身更有价值（别人能看到"哪条被验证过"）。

**⑤ 为什么采纳时"生成新版本"要做成可选？**
有时候建议是对的，但作者想自己改（不想直接用别人的措辞）；有时候建议只是"方向"，不涉及正文改动。
所以设计成两个选项：**仅标记** / **附带新正文并生成版本**。前者轻量，后者才能产生分数对比。

**⑥ 为什么版本来源要区分 `ADOPT_COMMENT`？**
版本时间线上要能看出"这一版是怎么来的"：粘贴（PASTE）、自己改（EDIT）、采纳社区建议（ADOPT_COMMENT）。
它能支撑一个很有说服力的数据：**"采纳社区建议后，平均分提升了多少"** —— 这是产品价值的量化证明。

**⑦ 为什么采纳也要做权限校验（不能采纳自己的评论）？**
作者给自己写一条评论然后"采纳"，会污染"有效建议"的信号，也会让采纳数变成自娱自乐。
规则简单（`comment.userId != post.userId`），代价极低。

## 14.3 实体与查询

```java
@Entity
@Table(name = "comment")
@Getter @Setter @NoArgsConstructor
public class Comment {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id;
    @Column(name = "post_id", nullable = false) private Long postId;
    @Column(name = "user_id", nullable = false) private Long userId;
    @Column(name = "parent_id") private Long parentId;
    @Column(name = "root_id") private Long rootId;
    @Column(nullable = false, length = 32) private String section = "OTHER";
    @Column(nullable = false, length = 1000) private String content;
    @Column(name = "like_count", nullable = false) private Integer likeCount = 0;
    @Column(name = "useful_count", nullable = false) private Integer usefulCount = 0;
    @Column(nullable = false) private Boolean adopted = false;
    @Column(name = "adopted_version_id") private Long adoptedVersionId;
    @Column(name = "adopted_at") private LocalDateTime adoptedAt;
    @Column(nullable = false, length = 16) private String status = "PUBLISHED";
    @Column(name = "created_at", nullable = false, updatable = false) private LocalDateTime createdAt;
    @PrePersist void onCreate() {
        if (createdAt == null) createdAt = LocalDateTime.now(ZoneOffset.UTC);
    }
}
```

```java
public interface CommentRepository extends JpaRepository<Comment, Long> {
```

> **一次查全量再内存组装**：一个帖子的评论通常 < 200 条，`WHERE post_id=?` 一次查完，然后在 Java 里分组成"顶层 + 回复"。比"先查顶层（分页）再对每条查回复"少 N 次查询。

## 14.4 评论服务

```java
@Service
@RequiredArgsConstructor
public class CommentService {

    private final CommentRepository commentRepository;
    private final PostRepository postRepository;
    private final VoteRepository voteRepository;
    private final UserRepository userRepository;
    private final PrivacyReviewService privacyReviewService;

    private static final List<String> SECTIONS =
            List.of("SUMMARY", "SKILLS", "EXPERIENCE", "PROJECT", "EDUCATION", "KEYWORDS", "OTHER");

    @Transactional
    public CommentVO create(Long userId, Long postId, CreateCommentRequest req) {
        Post post = postRepository.findByIdAndStatus(postId, "PUBLISHED")
                .orElseThrow(() -> new BizException(ErrorCode.POST_NOT_VISIBLE));

        Long parentId = req.parentId();
        Long rootId = null;

        if (parentId != null) {
            Comment parent = commentRepository.findByIdAndStatus(parentId, "PUBLISHED")
                    .orElseThrow(() -> new BizException(ErrorCode.COMMENT_NOT_FOUND));
            if (!parent.getPostId().equals(postId)) {
                throw new BizException(ErrorCode.PARAM_INVALID, "评论不属于该帖子");
            }
            if (parent.getParentId() != null) {
                throw new BizException(ErrorCode.COMMENT_DEPTH_EXCEEDED);   // 只支持两级
            }
            rootId = parent.getId();
        }

        // 评论同样要过个人信息审核
        var outcome = privacyReviewService.checkAndRecord(userId, "COMMENT_PUBLISH", req.content());
        if ("REJECTED".equals(outcome.review().getStatus())) {
            throw new BizException(ErrorCode.POST_PRIVACY_REJECTED,
                    Map.of("reviewId", outcome.review().getId(), "hits", outcome.hits()));
        }

        Comment c = new Comment();
        c.setPostId(postId);
        c.setUserId(userId);
        c.setParentId(parentId);
        c.setRootId(rootId);
        c.setSection(normalizeSection(req.section()));
        c.setContent(req.content());
        c.setStatus("PUBLISHED");
        c = commentRepository.save(c);

        post.setCommentCount(post.getCommentCount() + 1);
        postRepository.save(post);

        return toVO(c, userRepository.findById(userId).map(AppUser::getNickname).orElse("用户"));
    }

    /** 评论区展示：顶层评论分页，回复随顶层一起返回 */
    @Transactional(readOnly = true)
    public List<CommentVO> list(Long postId, String section, String sort, Long currentUserId) {
        List<Comment> all = "PROJECT".equals(section) || section != null
                ? commentRepository.findByPostIdAndStatusOrderByCreatedAtAsc(postId, "PUBLISHED")
                : commentRepository.findByPostIdAndStatusOrderByCreatedAtAsc(postId, "PUBLISHED");

        // 按 section 过滤（只过滤顶层；回复跟随父评论）
        List<Comment> tops = all.stream()
                .filter(c -> c.getParentId() == null)
                .filter(c -> section == null || section.isBlank() || section.equals(c.getSection()))
                .toList();

        Map<Long, List<Comment>> replies = all.stream()
                .filter(c -> c.getRootId() != null)
                .collect(Collectors.groupingBy(Comment::getRootId));

        // 排序：有用优先 / 最新
        Comparator<Comment> cmp = "newest".equals(sort)
                ? Comparator.comparing(Comment::getCreatedAt).reversed()
                : Comparator.comparing(Comment::getUsefulCount).reversed()
                            .thenComparing(Comment::getCreatedAt);

        tops = tops.stream().sorted(cmp).toList();

        // 批量查作者与我的投票，避免 N+1
        Set<Long> userIds = all.stream().map(Comment::getUserId).collect(Collectors.toSet());
        Map<Long, String> nicknames = userRepository.findAllById(userIds).stream()
                .collect(Collectors.toMap(AppUser::getId, AppUser::getNickname));

        Map<Long, Set<String>> myVotes = currentUserId == null ? Map.of()
                : voteRepository.findByUserIdAndTargetTypeAndTargetIdIn(
                        currentUserId, "COMMENT", all.stream().map(Comment::getId).toList())
                  .stream().collect(Collectors.groupingBy(Vote::getTargetId,
                          Collectors.mapping(Vote::getVoteType, Collectors.toSet())));

        return tops.stream()
                .map(t -> toVO(t, nicknames.get(t.getUserId()), myVotes.getOrDefault(t.getId(), Set.of()),
                        replies.getOrDefault(t.getId(), List.of()).stream()
                                .map(r -> toVO(r, nicknames.get(r.getUserId()),
                                        myVotes.getOrDefault(r.getId(), Set.of()), List.of()))
                                .toList(),
                        currentUserId))
                .toList();
    }
}
```

## 14.5 采纳

```java
@Service
@RequiredArgsConstructor
public class AdoptService {

    private final CommentRepository commentRepository;
    private final PostRepository postRepository;
    private final AnalysisReportRepository reportRepository;
    private final ResumeService resumeService;
    private final AnalysisService analysisService;

    @Transactional
    public AdoptResultVO adopt(Long userId, Long commentId, AdoptRequest req) {
        Comment comment = commentRepository.findByIdAndStatus(commentId, "PUBLISHED")
                .orElseThrow(() -> new BizException(ErrorCode.COMMENT_NOT_FOUND));

        Post post = postRepository.findByIdAndStatus(comment.getPostId(), "PUBLISHED")
                .orElseThrow(() -> new BizException(ErrorCode.POST_NOT_VISIBLE));

        // 只有帖子作者能采纳
        if (!post.getUserId().equals(userId)) throw new BizException(ErrorCode.ADOPT_FORBIDDEN);
        // 不能采纳自己的评论
        if (comment.getUserId().equals(userId)) throw new BizException(ErrorCode.ADOPT_FORBIDDEN);

        comment.setAdopted(true);
        comment.setAdoptedAt(LocalDateTime.now(ZoneOffset.UTC));

        Long newVersionId = null;
        Integer versionNo = null;

        if (req != null && req.updatedResumeContent() != null
                && !req.updatedResumeContent().isBlank()) {

            // 找到帖子来源简历（报告 → 版本 → 简历）
            AnalysisReport report = post.getReportId() == null ? null
                    : reportRepository.findById(post.getReportId()).orElse(null);
            if (report == null) {
                // 报告已删除，只能标记采纳
                commentRepository.save(comment);
                return new AdoptResultVO(commentId, true, null, null);
            }

            Long resumeId = resumeService.requireOwnedVersion(userId, report.getResumeVersionId())
                    .getResumeId();

            var version = resumeService.addVersion(userId, resumeId, new AddVersionRequest(
                    req.updatedResumeContent(),
                    req.changeNote() == null ? "采纳评论 #" + commentId : req.changeNote(),
                    VersionSource.ADOPT_COMMENT));

            newVersionId = version.getId();
            versionNo = version.getVersionNo();
            comment.setAdoptedVersionId(newVersionId);

            // 触发一次重新分析：让作者马上看到分数变化（异步）
            analysisService.create(userId, newVersionId, report.getJdId(), true);
        }

        commentRepository.save(comment);
        return new AdoptResultVO(commentId, true, newVersionId, versionNo);
    }
}
```

**这个流程串起来是**：

```
社区帖子（含报告快照）
   ↓ 作者点"采纳"
评论标记 adopted
   ↓ 附带修改后的正文
resume_version 新增一条（source=ADOPT_COMMENT，parent=发帖时的版本）
   ↓ 自动触发
analysis_report 新增一条（异步跑）
   ↓ 前端对比
76.8 → 84.2（+7.4）
```

**这就是"社区互评 → 简历改进 → 可量化提升"的完整闭环**，面试时按这个顺序讲。

## 14.9 报错怎么办

| 现象 | 原因 | 解决 |
|---|---|---|
| 三级回复没被拦 | 只判断了 `parent.parentId` 存在性 | 见 `create` 里的判断 |
| 评论树顺序错乱 | 回复和顶层混在一起排序 | 只在顶层排序，回复按 `createdAt` 升序 |
| 采纳报"版本不属于该简历" | 帖子来源简历被删了 | 已兜底为"仅标记" |
| 采纳后分数没变化 | 新分析还在跑 | 前端轮询，或去简历页看最新报告 |
| 评论列表 N+1 | 逐条查作者 | 批量 `findAllById` + `groupingBy` |
| 采纳后评论没有"已采纳"标记 | 只有 replies 渲染了状态 | 顶层和回复都要渲染 `adopted` 标签 |
| 删除评论后计数不对 | 只改了 status 没减计数 | `post.commentCount - 1` |

## 14.10 自测题

1. **为什么只做两级？** → UI 可读性 + 查询恒定 1 次（一次查全量内存分组）。
2. **为什么同时存 `parent_id` 和 `root_id`？** → 避免递归查询，读多写少场景下的反范式。
3. **为什么评论也要过 PII 审核？** → 评论里同样可能写手机号/微信号；审核器是通用的。
4. **采纳为什么要区分"仅标记"和"生成版本"？** → 前者轻量，后者才能产生可量化的分数对比。
5. **为什么不能在采纳时直接改原版本内容？** → 版本不可变，只能在它之上新增。
6. **采纳流程的价值闭环是什么？** → 社区建议 → 采纳 → 新版本 → 重新分析 → 分数提升可量化。
