## 1.2 为什么这样设计（面试可讲）

**① 为什么要有统一的响应体 `ApiResponse`？**
前后端分离时，前端需要在 `http.js` 里写一次拦截器就能处理所有接口的结果。如果有的接口返回裸对象、有的返回 `{"data":...}`、出错时又返回 Spring 默认的 `{"timestamp":...,"status":500}`，前端每个页面都要写特判。
统一成 `{code, message, data, traceId, timestamp}` 后：`code=0` 一律成功，非 0 一律失败且**业务码映射到指定 HTTP 状态码**（比如 43002 ↔ 422），前端只认一个字段。

**② 为什么业务码和 HTTP 状态码要"双轨"？**
只用 HTTP 状态码不够细（409 无法区分"用户名已存在"和"重复发布"）；只用业务码则会让浏览器、Nginx、监控系统都以为一切正常（全是 200）。
所以：**HTTP 码表达"大类"，业务码表达"具体原因"**。这样 Nginx 日志按状态码聚合就能看出"哪类错误在涨"，前端又能精确弹不同提示。

**③ 为什么要有 `traceId`？**
一次请求可能在 Filter、Security、Controller、Service、异步线程里各打一行日志。线上出问题时，用户截图只能给你时间点，你没法把 5 行日志串起来。
`TraceIdFilter` 生成一个 16 位 id 放进 `MDC`，logback 的 pattern 里带上 `[%X{traceId}]`，同时在响应体里返回 —— 用户报错时把 traceId 给你，`grep` 一下就能还原整条链路。这是"可观测性"最小的落地方式。

**④ 为什么异常处理放在一个 `@RestControllerAdvice` 里？**
如果每个 Controller 都写 `try/catch`，一是重复，二是容易漏（漏了就直接把 Java 堆栈吐给前端，既难看又泄露内部结构）。
统一处理的好处：**业务代码只管抛 `BizException(ErrorCode.XXX)`**，什么都不用管；框架异常（参数校验失败、没权限、JSON 解析失败）也在这里转成统一格式；最后留一个 `Exception` 兜底，记 ERROR 日志但只给前端"系统繁忙"。

**⑤ 为什么这一步要临时放开所有接口的安全校验？**
`spring-boot-starter-security` 在 classpath 上时，Spring 会**默认拦截所有请求**并生成一个随机密码。不配置的话，第一步打开 Swagger 都会 401。
所以先写一个"全放行"的 `SecurityConfig` 让它能跑，**步骤 3 会把它整个替换成 JWT 版本**。这是刻意留的临时实现，注释里写清楚。

### 1.4.0 ★ 先看这张表：每一步数据在哪

这是你最需要建立的直觉 —— **每一层之间传的是什么类型的东西**：

```
浏览器
  │  JSON 文本（"{"username":"alice"}"）
  ↓  —— Tomcat 解析 ——
HttpServletRequest（Java 对象，能取 header / body / 路径）
  ↓  —— TraceIdFilter 贴 traceId ——
  ↓  —— Security 验 token ——
  ↓  —— DispatcherServlet 查路由表 ——
Controller 方法
  │  入：@RequestBody 把 JSON 转成 LoginRequest 对象
  │  出：返回 ApiResponse<TokenResponse>
  ↓  —— 调用 ——
Service
  │  入：LoginRequest 对象 + userId
  │  出：TokenResponse（VO，不是 Entity！）
  ↓  —— 调用 ——
Repository
  │  入：username 字符串
  │  出：Optional<AppUser>（Entity）
  ↓  —— JDBC ——
MySQL
  │  结果集（一行行文本/数字）
  ↓  —— JPA 映射 ——
AppUser 对象（Entity）
  ↑  —— 原路返回，Service 把它转成 VO，Controller 包成 ApiResponse，Jackson 转 JSON ——
浏览器
```

**记住两个"转换点"：**

| 转换 | 发生在哪 | 谁做 |
|---|---|---|
| JSON → `XxxRequest` 对象 | Controller 的参数绑定 | **Spring 自动**（`@RequestBody`） |
| `Entity` → `XxxVO` | Service 里 | **你手写**（`UserVO.of(entity)`） |

> 第二个为什么必须手写？因为"哪些字段能对外暴露"是业务决策 —— 比如 `AppUser.passwordHash` 绝对不能出现在 VO 里。

**这就是 01B 文档的核心内容，建议完整读一遍。**

### 1.4.4 统一响应体

```java
package com.jianli.common;

import org.slf4j.MDC;

public record ApiResponse<T>(int code, String message, T data, String traceId, long timestamp) {

    public static <T> ApiResponse<T> ok(T data) {
        return new ApiResponse<>(0, "ok", data, MDC.get("traceId"), System.currentTimeMillis());
    }

    public static <T> ApiResponse<T> ok() {
        return ok(null);
    }

    public static <T> ApiResponse<T> fail(ErrorCode ec, T data) {
        return new ApiResponse<>(ec.getCode(), ec.getDefaultMessage(), data,
                MDC.get("traceId"), System.currentTimeMillis());
    }
}
```

> 用 `record` 而不是 `@Data` 类：值对象天然不可变，字段固定，Jackson 2.18 原生支持序列化。

### 1.4.5 业务异常

```java
package com.jianli.common;

public class BizException extends RuntimeException {

    private final ErrorCode errorCode;
    private final transient Object data;

    public BizException(ErrorCode ec) { this(ec, null); }

    public BizException(ErrorCode ec, Object data) {
        super(ec.getDefaultMessage());
        this.errorCode = ec;
        this.data = data;
    }

    public ErrorCode getErrorCode() { return errorCode; }
    public Object getData() { return data; }
}
```

> `data` 用 `transient`：异常对象可能被序列化到日志/链路追踪里，业务数据不该跟着走。
> 为什么带上 `data`：步骤 12 的"审核不通过"要把命中的敏感信息位置返回给前端，错误体里必须能挂载结构化数据。

### 1.4.6 全局异常处理

```java
package com.jianli.common;

import lombok.extern.slf4j.Slf4j;
import org.slf4j.MDC;
import org.springframework.http.ResponseEntity;
import org.springframework.http.converter.HttpMessageNotReadableException;
import org.springframework.security.access.AccessDeniedException;
import org.springframework.validation.FieldError;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.servlet.resource.NoResourceFoundException;

import java.util.List;

@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    /** 业务异常：HTTP 码由 ErrorCode 决定（如 43002 → 422） */
    @ExceptionHandler(BizException.class)
    public ResponseEntity<ApiResponse<Object>> handleBiz(BizException e) {
        ErrorCode ec = e.getErrorCode();
        log.warn("biz error code={} msg={}", ec.getCode(), e.getMessage());
        return ResponseEntity.status(ec.getHttpStatus())
                .body(ApiResponse.fail(ec, e.getData()));
    }

    /** @Valid 校验失败：返回每个字段的错误 */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ApiResponse<Object>> handleValid(MethodArgumentNotValidException e) {
        List<FieldErrorItem> items = e.getBindingResult().getFieldErrors().stream()
                .map(f -> new FieldErrorItem(f.getField(), f.getDefaultMessage()))
                .toList();
        return ResponseEntity.badRequest()
                .body(ApiResponse.fail(ErrorCode.PARAM_INVALID, items));
    }

    /** 请求体不是合法 JSON */
    @ExceptionHandler(HttpMessageNotReadableException.class)
    public ResponseEntity<ApiResponse<Object>> handleUnreadable(HttpMessageNotReadableException e) {
        return ResponseEntity.badRequest()
                .body(ApiResponse.fail(ErrorCode.PARAM_INVALID, null));
    }

    /** 访问了不存在的路径 */
    @ExceptionHandler(NoResourceFoundException.class)
    public ResponseEntity<ApiResponse<Object>> handleNoResource(NoResourceFoundException e) {
        return ResponseEntity.status(404).body(ApiResponse.fail(ErrorCode.NOT_FOUND, null));
    }

    /** 没权限 */
    @ExceptionHandler(AccessDeniedException.class)
    public ResponseEntity<ApiResponse<Object>> handleDenied(AccessDeniedException e) {
        return ResponseEntity.status(403).body(ApiResponse.fail(ErrorCode.FORBIDDEN, null));
    }

    /** 兜底：不把堆栈吐给前端 */
    @ExceptionHandler(Exception.class)
    public ResponseEntity<ApiResponse<Object>> handleOther(Exception e) {
        log.error("unexpected error, traceId={}", MDC.get("traceId"), e);
        return ResponseEntity.status(500)
                .body(ApiResponse.fail(ErrorCode.INTERNAL_ERROR, null));
    }

    public record FieldErrorItem(String field, String message) {}
}
```

> 顺序有讲究：Spring 按"最近匹配"选 handler，`BizException` 比 `Exception` 更具体，所以会被优先命中，不用手写 `@Order`。

### 1.4.7 请求追踪

```java
package com.jianli.common;

import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.slf4j.MDC;
import org.springframework.core.Ordered;
import org.springframework.core.annotation.Order;
import org.springframework.stereotype.Component;
import org.springframework.web.filter.OncePerRequestFilter;

import java.io.IOException;
import java.util.Optional;
import java.util.UUID;

@Component
@Order(Ordered.HIGHEST_PRECEDENCE)   // 必须最先执行，后面的日志才有 traceId
public class TraceIdFilter extends OncePerRequestFilter {

    public static final String TRACE_ID = "traceId";

    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res,
                                    FilterChain chain) throws ServletException, IOException {
        String traceId = Optional.ofNullable(req.getHeader("X-Trace-Id"))
                .filter(s -> !s.isBlank())
                .orElse(UUID.randomUUID().toString().replace("-", "").substring(0, 16));

        MDC.put(TRACE_ID, traceId);
        res.setHeader("X-Trace-Id", traceId);
        try {
            chain.doFilter(req, res);
        } finally {
            MDC.remove(TRACE_ID);      // 线程复用，不清会导致串号
        }
    }
}
```

> **`MDC.remove` 那行不能省**。Tomcat 线程池复用线程，不清理会让下一个请求继承上一个的 traceId，排查时会被误导。

## 1.6 报错怎么办

| 现象 | 原因 | 解决 |
|---|---|---|
| `could not open ...\jvm.cfg` | 直接敲了 `mvn`/`java`，用的是坏的 java8 | 用 `start-backend.bat`；或按 00 文档设置 `JAVA_HOME` |
| `Port 8080 was already in use` | 上次的进程没退 | `netstat -ano \| findstr :8080` 找 PID，`taskkill /F /PID <pid>` |
| 启动报 `Failed to configure a DataSource` | MySQL 没启动 | 服务管理器启动 `MySQL80` |
| 启动报 `Flyway validate failed` | 表结构与脚本对不上 | 本地开发期可 `init-db.bat` 重建；**别在生产这么干** |
| Swagger 打开是 401 | 临时 `SecurityConfig` 没生效 | 确认类上有 `@Configuration @EnableWebSecurity`，且有 `permitAll()` |
| 返回体里 `traceId` 是 null | `TraceIdFilter` 的 `@Order` 不是最高 | 加 `@Order(Ordered.HIGHEST_PRECEDENCE)` |
| 中文乱码 | 文件编码不是 UTF-8 | IDEA → Settings → File Encodings 全设 UTF-8 |
| `NoResourceFoundException` 编译不过 | Boot 版本低于 3.2 | 确认 `pom.xml` 里 Boot 是 3.5.10 |
| 日志没有 `[traceId]` | `logback-spring.xml` 没放在 `resources` 根目录 | 移动文件；确认文件名是 `logback-spring.xml`（带 `-spring`） |

## 1.7 自测题（面试前复习）

1. **为什么业务码和 HTTP 状态码要两套？** → 一句话：HTTP 表达大类便于运维聚合，业务码表达具体原因便于前端精确处理。
2. **`@RestControllerAdvice` 的异常处理顺序是怎么定的？** → 按异常类型的具体程度匹配，越具体越优先；`Exception` 永远最后兜底。
3. **`MDC` 是什么？为什么要 `remove`？** → 线程本地诊断上下文；线程池复用线程，不清理会串号。
4. **为什么统一响应体里要放 `traceId` 而不是只写在日志里？** → 用户报错时只能提供截图，把 traceId 返回给前端，用户反馈时能直接定位整条链路。
5. **`@EnableAsync` / `@EnableScheduling` 现在加了但没用，会影响启动吗？** → 不会，只是在需要时才有代理；提前加是为了避免后面"异步静默失效"的坑。
